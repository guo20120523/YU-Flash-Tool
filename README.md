# YU-Flash-Tool

### Android 原生分区工具 · 分区发现 / 受限备份 / 镜像检查

[![Build](https://github.com/guo20120523/YU-Flash-Tool/actions/workflows/android.yml/badge.svg)](https://github.com/guo20120523/YU-Flash-Tool/actions/workflows/android.yml)
[![Android](https://img.shields.io/badge/Android-8.0%2B-3DDC84)](#运行要求与兼容范围)
[![UI](https://img.shields.io/badge/UI-Jetpack%20Compose%20Material%203-6750A4)](#四个页面)
[![License](https://img.shields.io/badge/License-GPL--3.0--only-blue)](<LICENSE>)

**把分区信息、读取备份和镜像检查放进一个本地运行的 Android 应用。** YU-Flash-Tool 使用 Kotlin、Jetpack Compose 与 Material 3 构建，不是网页套壳，也不是 Magisk 模块。你可以在设备上主动授权 Root、查看经过验证的 by-name 分区目标、对符合策略的分区进行读取备份，并通过系统文件选择器检查本地镜像。

项目面向需要了解设备分区、核对镜像与保留读取记录的 Android 用户和开发者。主页支持整体上下滚动与五列表格左右滚动，也在围绕 Android 手表等小屏设备的反馈改进布局。

> [!IMPORTANT]
> 当前版本 **0.1.1-safety-preview** 是安全预览版，**真实分区写入仍关闭**。“写入检查”只负责导入和检查镜像，不会刷入设备。它不是通用刷机器、恢复工具或已经完成设备适配的救砖方案。

## 功能一览

| 功能 | 当前实现 | 使用边界 |
| --- | --- | --- |
| Root 授权与工具自检 | 用户主动申请；核对 uid 0；检查实际 Toybox 行为 | Root 不代表 Bootloader 解锁；自检会写应用临时文件，不写块设备 |
| 分区发现 | 检查限定的常见 by-name 目录，解析真实块路径、设备号和容量，合并展示别名 | 不是全盘扫描；不保证列出所有设备节点 |
| 分区浏览 | 名称搜索、名称/大小/类型排序、槽位/风险/可读取筛选 | 未知状态不作为已验证安全状态 |
| 读取备份 | 独立任务目录、临时文件、长度检查、SHA-256、配套元数据 | 拒绝数据类、挂载中/挂载未知及映射目标；在线备份不保证可恢复 |
| 本地镜像检查 | SAF 导入私有暂存；实际长度、内容签名、部分 boot 结构与哈希检查 | 不接受 sparse、压缩包、未知内容；识别类型不等于设备兼容 |
| 任务记录 | 持久化阶段记录、脱敏导出；启动时标记未完成任务为中断 | 不自动恢复、重试或续写 |
| 外观与小屏 | 深色/浅色/跟随系统、动态取色、紧凑列表、主页整体滚动 | 圆屏边缘、旋钮及全部对话框尚未完成专门验收 |
| 实际刷写 | **未开放** | 设备适配注册表为空，硬件写入方法直接拒绝 |

当前也**不提供**批量刷写、任意 Shell 输入、自动回滚、切槽、自动重启、解锁 Bootloader 或关闭 AVB 校验。

## 四个页面

### 主页：查看目标，再决定操作

显示设备型号、Android 版本、Root 状态及可获取的当前槽位。分区表固定为五列：

| 分区名称 | 分区大小 | 文件格式 | 读取 | 写入 |
| --- | --- | --- | --- | --- |
| 点击查看详细信息 | 可切换二进制容量单位 | 按内容识别 | 进入备份确认 | 当前按钮为“写入检查” |

点击名称或大小可查看原始字节数、实际块设备、设备号、槽位、风险、挂载/映射状态与别名。**上下滑动整个主页，左右滑动表格查看完整五列**，不必压缩操作按钮来容纳小屏。

### 任务：知道做了什么、停在哪里

查看阶段、时间、任务 ID、字节数与可用退出码。导入成功、备份校验成功和真实写入是不同概念，不以统一“成功”字样推断设备可启动。可导出经过字段裁剪的记录用于排障。

### 设置：调整外观与保守策略

设置主题、动态取色、列表密度、容量单位、备份目录大小写、完成通知、风险展示与诊断信息；提供手动清理私有暂存的入口。写入相关的电量和供电设置不会解除当前硬件写入限制。

### 关于：版本、作者与许可

查看构建版本、用途、隐私与风险说明、源码地址和 GPL v3 全文；支持复制开发者 QQ。

## 下载与安装

1. 打开 **[Releases](https://github.com/guo20120523/YU-Flash-Tool/releases)**，选择需要的预发布版本，先阅读其变更与已知限制。
2. 下载 **[主应用 APK（0.1.1 构建）](https://github.com/guo20120523/YU-Flash-Tool/releases/download/preview-4-1/YU-Flash-Tool-debug.apk)**。不要把名字含 `androidTest` 的测试 APK 当成主程序。
3. 根据该发布页的 SHA-256 校验文件核对下载内容，在自己的受控测试设备上安装。
4. 首次打开只浏览界面也可以；需要发现分区和读取时，再主动授权 Root。

每次主分支成功构建会发布一个独立预发布，包含主 APK、测试 APK、匹配提交的源码、测试与 Lint 报告、构建身份、许可和校验值。**版本号与构建标签不同**：例如 `0.1.1-safety-preview` 是应用版本，`preview-4-1` 是第 4 次工作流运行的第 1 次尝试。失败构建及 PR 不发布。

> [!WARNING]
> 当前提供的是 Debug 签名包，尚无持久的生产签名方案。不同 CI 构建可能签名不同而无法覆盖安装。遇到签名冲突时，先导出需要保留的任务记录，**不要直接卸载**；卸载会删除应用私有数据与暂存。不要为安装而关闭设备安全机制。

## 快速开始

### 1. 授权并查看分区

主页点击“了解用途并申请 Root” → 在设备 Root 管理器中处理授权 → 等待工具检测与分区发现 → 搜索或筛选目标 → 点击名称查看详情。授权超时或检测失败时先检查诊断，不要反复点击重试。

### 2. 读取并保留备份

设置下载目录 → 点击目标的“读取” → 核对设备、容量、保存位置和剩余空间 → 阅读风险后确认 → 等待任务完成 → 保留镜像与元数据。

默认使用 `/sdcard/download`。如果设备仅有 `/sdcard/Download`，需要在设置中明确选择，不静默替换。输出布局示意：

```text
<选择的下载目录>/YU-Flash-Tool/<设备标识>/<时间戳>-<任务ID>/
├── <分区名>.img
└── metadata.json
```

需要整分区容量之外至少 **64 MiB** 余量。文件扩展名和存在本身不是完成证明，须核对任务结果与配套元数据。

### 3. 选择本地镜像进行检查

点击“写入检查” → 通过系统文档选择器选择本地普通文件 → 等待私有暂存复制与检查 → 查看实际长度、类型和 SHA-256 → 关闭结果弹窗。

**这一流程不会进入真实写入。** 云端管道/流需要先保存到本地；把压缩包改成 `.img` 后缀不能变成合格镜像。详细异常处理见[用户指南](<docs/USER_GUIDE.md>)。

## 工作原理

### 分区发现与身份检查

```text
主动授权 Root → 验证 uid 与工具 → 限定目录查找 by-name
             → 解析真实块路径 → 核对设备号与容量
             → 检查挂载/映射并读取内容签名 → 合并别名展示
```

展示名称不是目标身份的全部依据。执行备份前还会刷新目标信息；设备路径、设备号、容量等变化时不能沿用旧目标继续。

### 读取备份与提交

```text
策略检查 + 目标复核 + 剩余空间检查
  → 独立目录中的 .img.partial
  → 读取完成 / 同步 / 长度检查 / SHA-256
  → 再次复核目标与备份 → 提交镜像和元数据 → 记录结果
```

提交失败后的回退只是最佳努力。掉电、进程被杀或重命名失败后，可能留下 `.partial`，也可能留下尚未完成提交的 `.img`；**不能只根据后缀判断可用性**。

### 核心事务与硬件写入的区别

核心模块已实现可审计的备份、备份验证、规范命名、再次检查、写入、同步与读回事务，并使用普通文件假设备进行故障模拟。**这不等于 Android 硬件适配器已支持刷写**：当前 [NoQualifiedDevices 注册表](<core/src/main/kotlin/io/yu/flash/core/Model.kt>)无合格设备，[RootDeviceAccess](<app/src/main/java/io/yu/flash/root/RootDeviceAccess.kt>)的实际写入方法直接拒绝。不要删除拦截后直接用于刷机。

## 安全与隐私

- **备份不等于能够恢复，哈希相符不等于设备能够启动。** 在线读取可能遇到一致性问题。
- 拒绝备份数据类目标（如 `userdata`、`metadata`、`cache`）、挂载中/挂载未知和映射目标；不提供强制忽略按钮。
- 应用不声明 INTERNET 权限，无广告或分析 SDK 配置。系统文档提供器与外部同步应用不在这个保证范围内。
- 备份可能含密钥、身份信息或个人数据，下载目录不是私有空间；避免无关应用访问及云同步。
- 进程内互斥、前台服务、通知及唤醒锁用于减少任务冲突和中断，不承诺系统永不杀进程。
- 异常提供器可能忽略取消，结束直接 `su` 进程也不能保证其所有后代都结束；不承诺任意阶段都可“安全取消”。
- 日志导出排除路径、指纹和错误原文等字段，但时间与分区名仍可能透露使用情况。

进一步说明见[安全设计](<docs/SAFETY_DESIGN.md>)。

## 常见问题

### 为什么有“写入检查”，却不能刷入？

镜像识别、目标兼容、Bootloader/AVB/回滚验证和实际硬件写入是不同层次。当前仅提供检查入口，没有完成设备认证，不会假装检查通过就能安全刷入。

### `od: /dev/block/mmcblk0rpmb: I/O error` 是 Root 失败吗？

不一定。RPMB 不是按普通块读取方式访问的存储区域，当前统一探测逻辑可能触发这个错误，而且重复别名可能带来重复提示。**0.1.1 尚未修复 RPMB 探测跳过问题**；不要给 RPMB 写密钥、格式化或执行写入测试。其他普通分区的 I/O 错误仍须单独调查。

### 手表上看不到分区表怎么办？

先确认安装的是 0.1.1 或更新版本：上下滑动主页到分区表，再左右滑动查看操作列。顶部和底部应用导航仍固定；圆屏、极端字体大小与对话框可能仍需改进。反馈请附型号、屏幕形状、分辨率/缩放及去敏截图。

### 为什么备份被拒绝，或者镜像导入失败？

常见原因包括挂载/映射/数据类目标、身份未知、空间不足、目录大小写不匹配、云端流文件、镜像超长、sparse/压缩包或未知内容。请按具体提示处理，不要通过改后缀或删除安全检查“修复”。

### 怎么反馈问题？

在 [Issues](https://github.com/guo20120523/YU-Flash-Tool/issues) 提供版本与构建标签、机型、Android/Root 方案、复现步骤、预期/实际行为和脱敏日志。**不要上传 Token、镜像、完整备份、设备指纹或含个人信息的元数据。** 也可联系开发者 QQ：3895958954。
