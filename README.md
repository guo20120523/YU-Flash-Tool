**在 Android 设备上查看分区、保留读取备份、核对本地镜像。**

YU-Flash-Tool 是使用 Kotlin、Jetpack Compose 与 Material 3 构建的原生 Android 应用，面向需要了解设备分区、检查镜像文件和记录操作过程的用户与开发者。它将分区信息、Root 读取、镜像检查与任务记录集中在一个本地界面中，无需通过任意 Shell 输入来完成这些操作。

项目重视目标身份核对、操作前确认和结果可追溯：不只展示分区名称，也检查实际设备路径与容量；不只生成备份文件，也记录长度、摘要与元数据；遇到不满足策略的目标时，明确拒绝而不是静默继续。

**[下载与发行说明](https://github.com/guo20120523/YU-Flash-Tool/releases)** · **[使用指南](<docs/USER_GUIDE.md>)** · **[文档中心](<docs/README.md>)** · **[问题反馈](https://github.com/guo20120523/YU-Flash-Tool/issues)**

> [!IMPORTANT]
> **真实分区写入未开放。** “写入检查”用于导入和检查镜像，不会将其刷入设备。本项目不是通用刷机器或自动恢复工具；请勿把镜像检查通过理解为可以安全刷写。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| **Root 授权与检测** | 由用户主动发起授权，核对 Root 身份与所需工具；未授权时仍可浏览设置和历史任务。 |
| **分区发现** | 从限定的常见 by-name 目录发现目标，解析真实块设备路径、设备号和容量，合并重复别名。 |
| **分区浏览** | 按名称搜索，按名称、大小或类型排序，按槽位、风险及可读取状态筛选；通过详情查看身份与状态信息。 |
| **读取备份** | 对符合策略的目标执行读取，使用独立任务目录和临时文件，检查长度与 SHA-256，并保存配套元数据。 |
| **本地镜像检查** | 通过系统文档选择器导入镜像，在应用私有暂存中核对实际长度、内容签名、部分结构及哈希，而非只看扩展名。 |
| **任务记录** | 持久化记录操作阶段和结果，支持脱敏导出，便于检查任务完成情况与定位异常。 |
| **外观与设置** | 支持跟随系统、浅色与深色主题，以及动态取色、列表密度、容量单位和通知等设置。 |

不提供任意 Shell 执行、批量刷写、自动回滚、自动切槽、自动重启、Bootloader 解锁或 AVB 绕过入口。

## 工作原理

### 分区发现：名称之外，还要核对身份

```text
主动授权 Root → 验证身份与工具 → 查找限定的 by-name 目录
             → 解析真实设备路径与容量 → 检查挂载、映射与内容签名
             → 整理分区列表及别名
```

分区名称不是目标身份的全部依据。执行读取前还会刷新信息，避免直接沿用已变化的设备路径、设备号或容量。列表出现一个目标，并不代表它可以备份或写入。

### 读取备份：从临时文件到校验结果

```text
策略检查 + 目标复核 + 空间检查
  → 读取到独立目录的临时文件
  → 同步 / 长度检查 / SHA-256
  → 复核目标与备份 → 提交镜像及元数据 → 记录结果
```

备份按任务分开保存，不把已有备份作为覆盖目标。文件存在、名称正确或扩展名为 `.img` 都不是完整成功的证明，应同时检查任务结果和配套元数据。掉电、进程终止或提交失败后可能留下未完成文件，不能只根据后缀判断可用性。

### 镜像检查：检查内容，不信任文件名

系统文档选择器提供文件 → 复制到私有暂存 → 按实际读取字节数核对长度 → 识别内容并计算摘要 → 展示检查结果。

检查不会修改原始文档，也不等同于设备兼容、AVB、回滚保护或启动验证。压缩包改成 `.img` 后缀不会成为合格镜像。

## 界面与设置

### 主页

集中显示设备信息、Root 状态和分区列表。表格按 **分区名称、分区大小、文件格式、读取、写入** 五列组织；点击名称或大小可查看真实块设备、设备号、原始字节数、槽位、别名及挂载/映射状态。“写入”列的检查入口不执行真实刷写。

### 任务

查看任务阶段、时间、任务 ID、字节数及可用退出码，按需导出脱敏记录。导入成功、备份校验成功和设备能够启动是不同结论，不应相互替代。

### 设置

- **外观**：主题、动态取色、列表密度与容量显示单位。
- **存储**：备份目录选择、私有暂存清理。
- **信息**：完成通知、风险展示与诊断信息。
- **策略**：相关安全选项不会绕过目标检查，也不会解除硬件写入限制。

### 关于

查看应用信息、开发者联系方式、源码地址、用途与风险说明，以及开源许可证。

## 快速开始

### 查看分区

在主页发起 Root 授权 → 在设备 Root 管理器中处理请求 → 等待检测 → 搜索或筛选目标 → 打开详情核对信息。

### 读取备份

选择备份目录 → 点击目标的“读取” → 核对目标、容量、保存位置及剩余空间 → 阅读风险并确认 → 等待任务结束 → 检查结果并保留镜像与元数据。

目录选择必须明确，不能把大小写不同的路径当成同一个位置。具体目录规则与空间要求见[用户指南](<docs/USER_GUIDE.md>)。

### 检查镜像

点击“写入检查” → 选择本地普通文件 → 等待复制与检查 → 查看实际长度、类型及 SHA-256。

这一流程不执行刷写。云端提供器返回的管道或流可能不被接受，应先保存为本地文件；不要靠修改后缀绕过内容检查。

## 运行要求

- **Android 设备**：系统版本须满足所选发行版的要求；源码配置见[应用构建配置](<app/build.gradle.kts>)。
- **Root 环境**：发现和读取分区需要可用的 `su`、Root 授权及工具检测通过。Root 不等于 Bootloader 已解锁。
- **访问条件**：依赖系统工具与设备信息接口；SELinux、Root 管理器和厂商系统差异可能限制访问。
- **存储空间**：备份和私有镜像暂存均需足够空间，实际需求以任务检查与提示为准。
- **本地文件访问**：镜像需能通过系统文档选择器以普通文件方式读取。

最低系统版本不等于全机型认证。动态分区、快照、非 A/B 布局及特殊设备节点不能仅因被识别就视为可操作目标；具体版本的限制以发行说明为准。

## 安全与隐私

- **备份不等于具有恢复手段，哈希相符不等于设备能够启动。** 在线读取也不保证文件系统一致性。
- 拒绝不符合读取策略的数据类、挂载中、挂载状态未知或映射目标，不提供强制忽略入口。
- 应用不声明 INTERNET 权限，无广告或分析 SDK 配置；外部文件提供器和同步应用不在这一保证范围内。
- 分区备份可能包含密钥、身份信息或个人数据。下载目录不是私有空间，应避免无关应用访问和云同步。
- 前台服务与任务互斥用于降低冲突和中断风险，不承诺系统永不终止进程，也不承诺所有阶段都能立即安全取消。
- 脱敏日志仍可能包含时间和分区名，分享前应自行检查。不应公开镜像、完整备份或敏感元数据。

更多策略、失败处理与残余风险见[安全设计](<docs/SAFETY_DESIGN.md>)。

## 常见问题

### 有 Root 就能操作所有分区吗？

不能。Root 只是访问条件之一；目标身份、挂载状态、映射关系、系统限制和应用策略仍然有效。检测失败不应通过反复重试或删除检查来处理。

### 为什么“写入检查”不执行刷写？

镜像识别与实际硬件写入是不同能力。工程中的硬件写入接口被明确阻断；检查结果不能代替设备适配和完整安全验证。不要移除拦截后直接用于刷机。

### 为什么备份或导入被拒绝？

常见原因有目标不符合读取策略、身份未知、空间不足、目录不匹配，以及文件不是可读取的本地普通镜像。请按具体提示和使用指南处理，版本相关问题可查看 Releases 与 Issues。

### 怎样判断任务是否完成？

查看任务结果、长度与摘要校验，以及备份的配套元数据。不要只看文件存在、扩展名正确或进度停止；不完整任务不会自动续写或恢复。

## 开发与构建

工程由 Android 应用层与纯 JVM 核心层组成：

| 入口 | 职责 |
| --- | --- |
| [应用模块](<app/build.gradle.kts>) | Compose 界面、Root/存储适配、服务、设置与任务记录 |
| [核心模块](<core/build.gradle.kts>) | 目标模型、安全策略、镜像解析与可审计事务 |
| [核心测试](<core/src/test/kotlin/io/yu/flash/core/SafetyTest.kt>) | 使用普通文件与假设备验证流程、故障处理及并发约束 |
| [构建与发布工作流](<.github/workflows/android.yml>) | 测试、Lint、APK 构建、对应源码与报告打包、发行发布 |

具备[构建说明](<docs/BUILD.md>)要求的工具链和依赖后，可在仓库根目录执行：

```sh
# 仅运行 JVM 核心测试
./gradlew -PcoreOnly=true :core:test

# Android Lint、主 APK 与仪器测试 APK 编译
./gradlew :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

编译测试 APK 不代表执行了 UI 测试，普通文件模拟也不代表设备验收。具体发行版本的实际结果请查看其 Releases 页面和配套报告；测试设计与证据说明见[文档中心](<docs/README.md>)。
