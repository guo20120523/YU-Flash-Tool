# YU-Flash-Tool

### Android 原生分区工具 · 分区发现 / 手动读取备份 / 直接 dd 写入

[![Build](https://github.com/guo20120523/YU-Flash-Tool/actions/workflows/android.yml/badge.svg)](https://github.com/guo20120523/YU-Flash-Tool/actions/workflows/android.yml)

**在 Android 设备上获取分区表、手动读取备份，并在阅读警告与免责声明、确认后将所选文件直接写入目标。**

YU-Flash-Tool 使用 Kotlin、Jetpack Compose 与 Material 3 构建，把 Root 访问、分区信息和任务记录集中在本地界面中，不提供任意 Shell 输入入口。写入采用固定 Toybox `dd` 命令，不再通过旧版镜像检查、兼容性预检、强制备份或读回验证流程。

**[下载与发行说明](https://github.com/guo20120523/YU-Flash-Tool/releases)** · **[使用指南](<docs/USER_GUIDE.md>)** · **[文档中心](<docs/README.md>)** · **[问题反馈](https://github.com/guo20120523/YU-Flash-Tool/issues)**

> [!WARNING]
> **直接写入会真实覆盖目标，没有写入安全性或兼容性检查。** 文件内容原样交给 `dd`，包括 sparse、压缩包和未知格式；不会展开、解压或转换。应用不强制备份，不核对文件与分区的大小、类型、槽位、AVB、Bootloader、挂载、动态分区、电量、温度或可写性。误写可能损坏正在使用的存储，导致数据丢失、无法启动或变砖。`dd` 与 `sync` 返回 0 不代表字节已验证、可启动或可恢复；没有真机写入验收，也没有安全取消保证。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| **一键获取分区表** | 用户主动发起 Root 授权和发现；运行时显示“正在读取分区表”。只探测限定的常见 by-name 路径，RPMB 在内容探测前跳过。 |
| **分区浏览** | 搜索、排序和筛选分区；查看名称、大小、类型及详情。展示信息不是写入许可或兼容性判断。 |
| **手动读取备份** | 独立操作，仍受保守读取策略限制；核对备份长度、SHA-256 并保存元数据。可能被拒绝，不会由写入自动触发。 |
| **文件暂存** | 从系统文档选择器的 `content://` URI 读取流，复制成应用私有普通文件；记录实际字节数，不解析镜像、不算写入校验哈希、不按类型或分区容量拒绝。 |
| **直接 dd 写入** | 一个危险确认框展示目标名、设备路径与文件字节数；阅读警告与免责声明并确认后直接写入，再单独执行 `sync`。无需准确输入目标名或兼容性预检。 |
| **任务记录** | 记录阶段及可用退出码，支持脱敏导出；拒绝应用当前运行任务的重复提交，但不锁定其他进程或工具。 |
| **外观与设置** | 跟随系统、浅色/深色、动态取色、列表密度、容量单位和通知设置。 |

不提供任意 Shell、批量刷写、自动重试、自动回滚、自动切槽、自动重启、Bootloader 解锁或 AVB 绕过入口。

## 工作原理

### 分区发现与手动读取

主页点击 **“一键获取分区表”**，在设备 Root 管理器中处理授权请求，等待 **“正在读取分区表”** 完成。发现阶段整理设备路径、容量、别名和内容类型；Root 工具自检会写应用自有普通临时文件，不以块设备为输出。发现有边界，不承诺列出全部设备或支持整盘目标。

手动“读取”仍使用独立的保守策略：检查目标、目录和空间，读取至临时文件，检查长度与 SHA-256 后提交备份及元数据。DATA、挂载中/挂载未知、映射等对象可能被拒绝。**这与直接写入是两条路径：读取被拒绝不会为写入增加保护，写入也不会自动生成备份。**

### 文件选择与直接写入

```text
选择分区 → 选择 content URI → 流复制到私有普通文件
  → 一个危险确认框：目标名 / 设备路径 / 文件字节数 / 警告与免责声明
  → 明确确认 → 固定 toybox dd → dd 返回 0 后单独 toybox sync
  → 记录命令结果（没有读回验证）
```

固定写命令为：

```text
/system/bin/toybox dd if=<引用后的私有文件路径> of=<引用后的已发现 /dev/block 路径> bs=1048576
/system/bin/toybox sync
```

这是两次独立命令调用，不是任意命令输入模板。路径引用、基本路径限制和应用内任务串行化保留，但不是设备安全检查。短文件不会自动填满分区尾部；过长文件可能在部分写入后失败。压缩或 sparse 文件会按其容器字节写入，不会变成展开后的镜像。原始选中文档不改写。

`dd` 非零即终止该流程，不执行后续成功流程、不自动重试或回滚；`sync` 出错也不能报成功。没有固定目标 FD 的旧版备份哈希比对或全量读回保证。

## 界面与设置

- **主页**：设备与 Root 状态、获取分区表按钮和五列表格（分区名称、分区大小、文件格式、读取、写入）。点击名称或大小查看详情。
- **任务**：查看阶段、时间、任务 ID、字节数及可用退出码。导入完成、手动备份验证完成、直接写入命令完成是不同结论。
- **设置**：调整外观、手动备份目录和通知；无当前运行任务时可手动清理私有暂存，不自动删除备份。没有强制备份、哈希、最低电量等直接写入保护开关。
- **关于**：用途、风险、作者、源码地址与许可证。

图标使用离线打包的官方 Material Symbols Rounded，来源和许可见[图标设计](<docs/ICON_DESIGN.md>)。

## 快速开始

### 查看或读取分区

点击“一键获取分区表” → 主动授予 Root → 等待读取完成 → 核对目标详情。需要手动备份时，明确选择备份目录，点击“读取”并确认；完成后保留镜像及配套元数据。备份可能被读取策略拒绝，也不保证可恢复。

### 直接写入文件

点击目标“写入” → 选择文件 → 等待私有复制 → 核对危险确认框中的**目标名、设备路径、实际文件字节数** → 阅读警告与免责声明 → 明确确认后开始直接 `dd`。关闭确认框不会提交写入。

这里没有独立“镜像检查通过”步骤，也没有准确输入分区名、强制备份、兼容性放行或读回。**提交后不要把界面停止、取消、超时或失败当作 Root 后代 `dd` 已经停止。** 详见[用户指南](<docs/USER_GUIDE.md>)。

## 运行要求

- Android 版本须满足所选发行版要求；源码要求见[应用构建配置](<app/build.gradle.kts>)。
- 可用的 `su`、用户 Root 授权、系统 Toybox 及设备信息接口；SELinux、Root 管理器、内核或厂商差异可能导致失败。
- 文档提供器能返回可读取的内容流，私有存储有足够空间完成复制。空间或读取错误仍可使暂存失败，但应用不按目标容量做镜像适配判断。
- 手动备份需要独立存储空间并满足读取策略；这不是直接写入的前置条件。

Root 不等于 Bootloader 解锁；不检查某个条件不等于系统会允许操作，更不等于操作正确。RPMB 仍不作为普通内容设备探测；没有“所有分区/整盘均支持”的承诺。

## 风险与隐私

- **没有自动备份、镜像解析、哈希或读回验证。** AVB、回滚索引、机型、当前槽位、挂载和动态存储风险由用户自行判断；可能损坏仍被系统使用的设备。
- 应用只阻止自己的当前任务重复执行，不锁定其他进程或其他 Root 工具。旧不确定写入标记不再阻止直接流程；旧进程遗留的 `dd` 也可能仍在运行。
- 前台服务、超时及取消只能尽力管理应用和直接 `su` 进程，不能保证其后代 `dd` 退出。失败后不要反复刷写或盲目重启，应保留记录并核实设备状态。
- 手动备份的哈希只说明相应文件检查结果，不能证明在线一致性、可启动性或恢复能力。
- 应用不声明 INTERNET 权限，无广告或分析 SDK 配置；外部提供器、其他 Root 进程与同步软件不在这一范围内。
- 备份可能含密钥、身份信息和个人数据。下载目录不是私有空间；脱敏日志仍有时间和分区名，分享前应自行检查。

## 常见问题

### sparse、ZIP 或未知文件能选吗？

能作为原始字节输入，不会按格式拒绝，但**不是 sparse 展开、刷包或解压支持**。把压缩包写进分区通常不是你想要的结果；改后缀也不会转换内容。

### “完成”意味着刷写正确吗？

不意味着。直接写入 `SUCCESS` 仅表示 `dd` 和随后 `sync` 都返回 0；没有读回哈希、兼容性或启动验证。文件过短、错误格式或错误目标仍可能得到命令成功。

### 为什么备份被拒绝，写入却仍可确认？

手动读取保留旧保守 `SafetyPolicy`，直接写入不使用它。这不是读取失败后的恢复建议，也不应据此认为写入更可靠。
