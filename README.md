# YU-Flash-Tool

### Android 原生分区工具 · 分区发现 / 完整备份 / dd 写入与读回校验

[![Build](https://github.com/guo20120523/YU-Flash-Tool/actions/workflows/android.yml/badge.svg)](https://github.com/guo20120523/YU-Flash-Tool/actions/workflows/android.yml)
[![Platform](https://img.shields.io/badge/Platform-Android-3DDC84)](#运行要求)
[![UI](https://img.shields.io/badge/UI-Jetpack%20Compose%20Material%203-6750A4)](#界面与设置)
[![License](https://img.shields.io/badge/License-GPL--3.0--only-blue)](<LICENSE>)

**在 Android 设备上获取分区表；确认写入后，先自动完整备份并复核，再通过固定 `dd` 写入，最后校验写入范围的长度与 SHA-256。**

YU-Flash-Tool 使用 Kotlin、Jetpack Compose 与 Material 3 构建，把 Root 访问、分区信息和任务记录集中在本地界面中，不提供任意 Shell 输入入口。活动路线仍是直接 `dd`，但**自动备份、备份复核和写后读回是不可跳过的步骤**，不是可关闭的保护开关。

**[下载与发行说明](https://github.com/guo20120523/YU-Flash-Tool/releases)** · **[使用指南](<docs/USER_GUIDE.md>)** · **[文档中心](<docs/README.md>)** · **[问题反馈](https://github.com/guo20120523/YU-Flash-Tool/issues)**

> [!WARNING]
> **备份和字节校验不等于兼容性、可启动性或可恢复性保证。** 文件内容原样交给 `dd`；sparse、压缩包和未知格式不会展开、解压或转换。没有恢复镜像格式、AVB、回滚、槽位、Bootloader、电量等兼容性准入。强制备份沿用保守读取策略，DATA、挂载中/挂载状态未知、映射/映射状态未知、身份或容量未知、空间不足等情况会在写入前被拒绝，不能理解为“所有目标都能写”。短镜像仅校验前缀，未触及的尾部不验证；过长镜像可能部分写入后失败。当前没有真机写入验收，也没有安全取消或掉电持久性保证。

## 核心功能

| 功能 | 说明 |
| --- | --- |
| **一键获取分区表** | 用户主动发起 Root 授权和发现；运行时显示“正在读取分区表”。只探测限定的常见 by-name 路径，RPMB 在内容探测前跳过。 |
| **分区浏览** | 搜索、排序和筛选分区；查看名称、大小、类型及详情。展示信息不是兼容性或写入许可。 |
| **完整备份** | 可单独手动读取；每次写入前还会自动备份整个目标分区，并强制复核长度、SHA-256 和提交元数据。读取策略拒绝时不进入写入。 |
| **文件暂存** | 将系统文档选择器的 `content://` 流复制成私有普通文件，记录实际字节数；不解析或转换镜像。写入前另行测量实际长度与 SHA-256。 |
| **直接 dd 与读回** | 危险确认后依次完成备份、复核、源摘要、`dd`、独立 `sync` 和精确字节范围读回；再次核对源文件，全部满足才记录 `SUCCESS`。 |
| **任务记录** | 记录阶段及可用退出码，支持脱敏导出；拒绝应用当前运行任务的重复提交，但不锁定其他进程或工具。 |
| **外观与设置** | 跟随系统、浅色/深色、动态取色、列表密度、容量单位、备份目录和通知设置。 |

不提供任意 Shell、批量刷写、自动重试、自动回滚、自动切槽、自动重启、Bootloader 解锁或 AVB 绕过入口。

## 工作原理

### 分区发现与备份

主页点击 **“一键获取分区表”**，在设备 Root 管理器中处理授权请求，等待 **“正在读取分区表”** 完成。发现整理设备路径、容量、别名和内容类型；Root 工具自检写入应用自有普通临时文件，不以块设备为输出。发现有边界，不承诺列出全部设备或支持整盘目标。

在设置中明确选择 `/sdcard/download` 或 `/sdcard/Download`，不存在或不可写时**不静默回退**。备份需要整个分区大小加至少 **64 MiB** 可用余量，在唯一任务目录中先写 `.partial`，同步并核对长度、SHA-256，再提交镜像及元数据。写入任务必须继续通过 `verifyBackup`，不能跳过或拿手动备份代替本次自动备份。备份文件校验不证明在线一致性或实际恢复能力。

### 文件选择与直接写入

```text
选择分区 → 选择 content URI → 流复制到私有普通文件
  → 危险确认框：目标名 / 设备路径 / 实际字节数 / 警告与免责声明
  → 明确确认 → 按现有备份策略自动完整备份 → verifyBackup
  → 测量写前源文件实际长度和 SHA-256
  → 固定 toybox dd → 仅 dd 返回 0 后独立 toybox sync
  → 只读助手流式读回目标的精确写入范围，核对长度和 SHA-256
  → 再次核对源文件长度和 SHA-256，检测修改 → SUCCESS
```

固定写命令为：

```text
/system/bin/toybox dd if=<引用后的私有文件路径> of=<引用后的已发现 /dev/block 路径> bs=1048576
/system/bin/toybox sync
```

这是两次独立调用，不是任意命令输入模板。只读读回助手由已安装 APK 经 `app_process` 启动，按写前源长度流式计算目标摘要，不生成另一份大型临时镜像，也不以可能掩盖读取错误的 Shell 管道判断成功。

`dd` 按原始字节写入，不补零、清尾、解压或展开 sparse。短镜像只验证从偏移 0 开始的相同长度前缀，**未写尾部不在验证范围内**；没有“必须与分区等长”的兼容性门槛，超长输入可能部分改写后才失败。原始选中文档不改写。

备份或复核失败不调用写入；写入后的失败不表示目标未改写。`dd`、`sync`、读回、长度/摘要比较或源文件复核任何一项失败都不能记录成功，不自动重试、回滚或重启。**没有贯穿备份、写入和读回的固定目标 FD，也不能保证 Root 后代 `dd` 的生命周期。**

## 界面与设置

- **主页**：设备与 Root 状态、获取分区表按钮和五列表格（分区名称、分区大小、文件格式、读取、写入）。点击名称或大小查看详情。
- **任务**：查看阶段、时间、任务 ID、字节数及可用退出码。导入完成、备份验证完成、写入范围验证完成是不同结论。
- **设置**：调整外观、备份目录和通知；无当前运行任务时可手动清理私有暂存，不自动删除备份。自动备份与读回不是可关闭选项。
- **关于**：用途、风险、作者、源码地址与许可证。

图标使用离线打包的官方 Material Symbols Rounded，来源和许可见[图标设计](<docs/ICON_DESIGN.md>)。

## 快速开始

### 查看或手动备份分区

点击“一键获取分区表” → 主动授予 Root → 等待读取完成 → 核对目标详情。在设置中明确选择备份目录；需要单独备份时，点击“读取”并确认，完成后保留镜像与配套元数据。备份可能被策略拒绝，也不保证可恢复。

### 写入文件

选好备份目录并准备足够空间 → 点击目标“写入” → 选择文件 → 等待私有复制 → 核对危险确认框中的**目标名、设备路径、实际文件字节数** → 阅读警告与免责声明 → 明确确认。之后自动完成全分区备份、复核、写入和精确范围读回，不能跳过备份直接刷写。关闭确认框不会提交任务。

没有独立的镜像格式/设备兼容性放行步骤，也不要求准确输入分区名。**提交后不要把界面停止、取消、超时或失败当作 Root 后代 `dd` 已停止。** 详见[用户指南](<docs/USER_GUIDE.md>)。

## 运行要求与隐私

- Android 版本须满足所选发行版要求；源码要求见[应用构建配置](<app/build.gradle.kts>)。
- 可用的 `su`、用户 Root 授权、系统 Toybox 及设备信息接口；SELinux、Root 管理器、内核或厂商差异可能导致失败。
- 私有存储足够暂存源文件；明确选择的下载目录足够容纳**整个目标分区加 64 MiB 余量**，并满足现有备份策略。空间检查不是容量预留。
- 不检查 AVB、回滚、槽位、Bootloader 或电量兼容性不代表条件正确；Root 也不等于 Bootloader 解锁。RPMB 不作为普通内容设备探测。
- 只串行化自身任务，不锁其他进程。备份通过后状态仍可改变；不承诺安全取消、掉电后持久、可启动或可恢复。
- 应用不声明 INTERNET 权限，无广告或分析 SDK 配置；外部提供器、其他 Root 进程与同步软件不在这一范围内。
- 备份可能包含密钥、身份信息和个人数据。下载目录不是私有空间；脱敏日志仍含时间和分区名，分享前应自行检查。

## 常见问题

### sparse、ZIP 或未知文件能选吗？

能作为原始字节输入，但**不是 sparse 展开、刷包或解压支持**。将容器原样写进分区通常是不正确且危险的；读回摘要相符也不会让它变成正确镜像。

### `SUCCESS` 意味着刷写正确吗？

只表示本次自动备份及复核完成、`dd`/`sync` 成功、读回范围的实际长度和 SHA-256 与写前源一致，且源文件复核一致。**不验证短镜像之外的尾部，不证明格式、兼容性、启动、恢复或掉电持久性。**

### 为什么备份被拒绝时不能写？

自动完整备份是强制前置条件，沿用现有 `SafetyPolicy.backup` 和备份实现。DATA、挂载/映射或其状态未知、身份/容量未知、目录不可用及空间不足等拒绝不能绕过；因此不是所有发现目标都支持写入。
