## 当前能力与风险边界

主页通过“一键获取分区表”主动请求 Root 并发现分区，实际加载文字为“正在读取分区表”。发现范围有限，RPMB 在内容探测前跳过，不承诺整盘或所有块设备支持。

**活动写入仍用固定 `dd`，但必须先自动完整备份并复核，写后必须读回校验。** 文件从 `content://` 流复制到私有普通文件，不解析或转换格式；sparse、压缩包和未知内容均作为原始字节，不展开、不解压。危险确认展示目标名、设备路径、实际字节数和免责声明，不要求准确输入名称。

确认后先沿用 `SafetyPolicy.backup` 与备份实现，在明确选择的 `/sdcard/download` 或 `/sdcard/Download` 建立唯一任务目录；无静默回退。需要整分区大小加 **64 MiB** 余量，先写 `.partial`，同步、核对长度/SHA-256 并提交元数据，再强制执行 `verifyBackup`。**备份策略不允许的目标不能写**，包括 DATA、挂载/映射或其状态未知、身份/容量未知等；不把未知风险分类本身等同于必然拒绝。

备份复核后测量源文件实际长度及 SHA-256，执行固定 `dd`，仅其返回 0 后单独 `sync`。只读助手从已安装 APK 经 `app_process` 流式读取目标的精确范围，长度/摘要须与写前源一致；再次复核源文件以检测修改。不生成另一份大型临时镜像，不以 Shell 管道隐藏读取错误。全部成功才记录 `SUCCESS`。

**短输入只验证写入前缀，不验证未触及尾部；超长输入可能部分写入后失败。** 未恢复格式、AVB、回滚、槽位、Bootloader、电量等兼容性准入，也未恢复旧固定 FD 写入事务。备份和读回不保证在线一致性、启动、恢复或掉电持久性。

应用仅串行化自身当前任务，不锁定其他进程/工具。继承的备份拒绝（包括读取路径互锁）会阻止进入写入，但不是贯穿 `dd` 的跨进程锁。取消、超时、服务停止、失败或页面空闲不能证明 Root 后代 `dd` 已停止；没有安全取消、自动重试、回滚或重启。

## 如何理解验证用语

- **实现说明／静态核对**：描述源码路径或本次契约，不等于编译、运行或设备验证成功。
- **测试修订中／待 CI**：没有对应执行报告前，不写成“通过”，不猜测当前数量。
- **编译通过**：不等于 UI 启动、仪器测试执行或真机读写验收。
- **单元模拟通过**：只覆盖对应运行中的假执行器、普通文件或内存端点，不等于 Root/块设备验证。
- **历史证据**：旧直接路线及旧受限 raw 结果不能转移为本次强制备份/读回的通过证据；旧固定 FD、root 锁/token 等也没有随之恢复。
- **写入成功**：表示自动备份及复核、写入/同步、精确范围长度/SHA-256 比较与源复核完成；不是格式、兼容性、可启动性或恢复认证。
- **正式发行**：指版本、签名与产物的发布方式；原发布证书应保持不变，实际构建、签名、证书比对和发布状态须由本次证据确认。
- **设备验收**：应有机型、系统/Root 环境、步骤与日志。当前没有本次写入真机验收或完整适配清单。

本次新测试、构建、Lint、签名及 GitHub 发布结果均等待对应 CI/产物证据；文档修订没有运行这些操作。既有 **104 项（28 项旧直接路线 + 76 项旧受限路线）**仅作为历史统计，当前测试数量待 CI。既有 **4 项 UI 仪器测试仅编译、未执行**，不作为本次 UI 通过证据。

## 文档与产物版本

项目首页和通用指南不维护逐版本更新列表或固定结果数量。变化、修复、限制和实际构建结果统一写在 Releases；发行说明源文档是发布输入，不是累积更新日志。

主分支文档可能领先于 APK。以所选 Release 的完整提交、说明、源码和校验资料为准；文档更新不会让旧 APK 获得新能力，也不会使未运行测试变成通过。
