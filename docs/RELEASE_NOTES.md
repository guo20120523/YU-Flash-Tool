# 1.0.1

> **本次恢复强制自动完整备份与写后读回校验，活动写入仍采用固定 Toybox `dd`。** 用户确认后必须先完整备份目标并通过 `verifyBackup`；写入和同步后，精确字节范围的长度/SHA-256 必须与写前源一致，并再次复核源文件，才能成功。备份或校验不可跳过。**这不是镜像兼容性、设备安全、可启动性、可恢复性或掉电持久性认证。** 本文是发布输入；实际 CI、签名与产物证据由工作流追加在后面，GitHub 发布状态以发行页面为准；文档本身不预先宣称完成。

## 本次变化

### 1. 确认后必须先备份完整分区

- 保留单个危险确认框，展示目标名、路径、源文件实际字节数、警告与免责声明；不要求准确输入目标名。
- 不再是确认后立即 `dd`。每次写入任务自动读取**整个目标分区**，不是只备份将写入的前缀；已有手动备份不能替代本次自动备份。
- 复用现有 `SafetyPolicy.backup` 和备份实现，不新建绕过读取限制的通道。DATA、挂载中/挂载状态未知、映射/映射状态未知、无效或未知容量/身份等不能通过；`Risk.UNKNOWN`/`Risk.CRITICAL` 分类本身不一定拒绝读取。
- 使用设置中明确选择的 **`/sdcard/download` 或 `/sdcard/Download`**；目录不存在或不可写时失败，绝不静默切换大小写或回退另一位置。
- 空间至少为完整分区容量加 **64 MiB**；短镜像也不减少备份需求。空间检查不是容量预留，其他进程仍可耗尽空间。
- 每次建立唯一任务目录，先写 `.img.partial`，同步、检查完整长度与 SHA-256，复核目标身份和文件摘要后提交镜像及元数据。不覆盖已有任务备份；孤立镜像或 `.partial` 不是完整备份成功。
- 写入协调器必须再执行 **`verifyBackup`**，核对文件长度、摘要及提交元数据。策略、身份、读取路径互锁、目录、空间、备份或复核任一失败都不得启动本次 `dd`。

**影响：不满足现有备份政策的目标不能写。** 本版不是“所有分区/整盘均可无条件直接写入”，也没有“跳过备份继续”选项。

### 2. 源摘要与写后精确范围校验

- 文件仍从 `content://` 流复制到私有普通文件，不修改原文档，不按镜像格式解析、解压、展开或转换。
- 自动备份及复核后，重新测量私有源的**实际长度和 SHA-256**，作为写前基准，不只依赖提供器长度或导入时统计；与已确认的导入字节数不符或摘要无效时不启动 `dd`，但不要求源与分区等长。
- 仍使用固定 `/system/bin/toybox dd`，保留基本路径限制与 Shell 引用，不提供任意 Shell。仅 `dd` 返回 0 后独立调用 `/system/bin/toybox sync`。
- 写后由**只读助手**通过已安装 APK 的 `CLASSPATH` 和 `app_process` 流式读回目标 `[0, 写前源长度)`，核对实际长度和 SHA-256。读取不足、I/O 异常、助手失败或结果不符均不能成功。
- 不生成另一份大型临时读回镜像，不依赖 `dd | sha256sum` 等可能掩盖上游读取错误的 Shell 管道。
- 最后再次测量源文件长度/SHA-256，检测相对写前基准的变化；读回比较使用的是**写前源**，不能用已改变的源重定义成功基准。这不是从导入起锁定内容，也不能排除检查之间修改后又恢复的竞态。
- 自动备份、`verifyBackup`、写前源摘要、`dd`、`sync`、精确范围读回与源复核全部成功后，才记录 `SUCCESS`。只有 `dd`/`sync` 返回 0 已不再足够。

```text
明确确认
  → 现有策略准入 → 完整自动备份 → verifyBackup
  → 写前源实际长度 + SHA-256
  → 固定 dd → 独立 sync
  → 只读助手精确范围读回长度/SHA-256，与写前源比较
  → 源长度/SHA-256 再复核 → SUCCESS
```

固定写入与同步命令（两次独立调用）：

```text
/system/bin/toybox dd if=<引用后的私有文件路径> of=<引用后的已发现 /dev/block 路径> bs=1048576
/system/bin/toybox sync
```

### 3. 保留的界面、发现与任务边界

- 修复主页重复“点击获取分区表”提示：只保留一个 **“一键获取分区表”** 按钮，初始诊断为空；读取时仅显示一次 **“正在读取分区表”**，隐藏旧诊断。详细诊断也不会重复渲染同一提示；新增两项仪器回归断言，编译与执行状态单独记录。
- 日志持久化与列表刷新分离：列表刷新失败单独警告，不把已保存的 SUCCESS 改记为写入失败；通知刷新也不影响已提交审计结果。短 SQLite 提交处理取消边界，不延长设备 I/O 的不可取消范围。
- 保留搜索、排序、详情、手动读取、任务及设置。
- RPMB 仍在普通内容探测前按别名及真实设备名跳过，不提供 RPMB 读写/密钥功能，不承诺整盘支持。
- 应用内串行化当前任务，重复提交拒绝而不排队；不锁其他进程/Root 工具。
- 复用备份意味着旧读取路径互锁的拒绝可能阻止任务；**不等于恢复旧固定 FD、root 独占锁/token 或为当前 `dd` 提供持久意图与生命周期保证**。
- 无自动重试、回滚、切槽或重启。前台服务、取消、超时、进程退出都不保证 Root 后代 `dd` 停止。

## 重要限制与风险

1. **没有恢复完整兼容性准入。** 镜像格式、AVB、回滚索引、槽位、Bootloader、电量、温度等旧检查未恢复；Root 不等于 Bootloader 解锁，用户确认和哈希相符不证明适配。
2. **原始字节完全不变。** sparse、ZIP/其他压缩包和未知内容不会展开、解压或转换；容器字节与目标读回一致，仍可能是错误且破坏性的结果。
3. **短镜像只验证前缀。** 未触及尾部不在写后验证范围内；全分区备份不等于全分区写后校验。不会补零或清尾。空文件也不是有效刷写。
4. **超长镜像可能先破坏后失败。** 没有恢复输入与分区等长/容量适配门槛，可能在部分写入后才报容量或 I/O 错误；不能以失败推断未写入。
5. **没有固定目标 FD 和全系统锁。** 备份、`dd`、读回分别打开路径，读回身份不能证明 dd 当时的 FD 身份。dd 读到 EOF，若源被外部追加再恢复，额外字节可能写到已验证前缀以外而未被发现；前后摘要不是不可变源或严格写入范围保证。备份准入拒绝挂载/映射或未知状态，不代表整个任务期间状态永远安全。
6. **没有安全取消或掉电持久性保证。** `sync` 加读回不是硬件掉电认证；失败、超时、取消、服务停止、页面空闲或无终态记录不证明后台 `dd` 已停。
7. **备份不是一致性快照或恢复认证。** 下载目录可能被同步、篡改或耗尽空间；镜像和元数据分开提交，不是跨文件原子事务。保留完整材料并独立准备救援途径。
8. **无本次真机、Root 写入、断电、启动或恢复验收。** 普通文件模拟、Lint、构建、签名验证和正式发布都不能升级为硬件安全认证。

遇到失败应停止重复操作，保留记录和已有备份，由有能力的人员核实进程与设备状态。不要以重试、删标记、清数据、卸载或盲目重启代替故障判断。

完整流程与边界见[用户指南](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/USER_GUIDE.md)及[安全设计](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/SAFETY_DESIGN.md)。活动源码入口为 [DirectFlash](https://github.com/guo20120523/YU-Flash-Tool/blob/main/core/src/main/kotlin/io/yu/flash/core/DirectFlash.kt)、[DirectDdWriter](https://github.com/guo20120523/YU-Flash-Tool/blob/main/app/src/main/java/io/yu/flash/root/DirectDdWriter.kt)及[备份实现](https://github.com/guo20120523/YU-Flash-Tool/blob/main/app/src/main/java/io/yu/flash/root/RootDeviceAccess.kt)，不是旧 RootWriter 写入事务。
