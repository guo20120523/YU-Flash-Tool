# 0.2.1-raw-preview · Material Symbols 图标统一

> **本应用仍包含可实际覆盖分区的实验性 raw 写入功能，尚未完成真机写入验收。** 本次只更新图标、视觉呈现、图标许可与验证配置，不修改刷写策略、Root 写入组件、备份或事务逻辑。新版外观不等于新增机型兼容或安全认证。

## 本次变化

### 应用图标

- 用 Google 官方 Material Symbols Rounded `flash_on` 填充图形替换缺省应用图标。
- 提供 Android 8+ 自适应图标，中央图形适应启动器圆形/圆角等蒙版；背景和前景采用 M3 基线容器色对。
- 提供 Android 13+ monochrome 层，支持启用主题图标的兼容启动器。普通图标并不直接跟随应用内 Compose 动态配色。

### 应用内与通知图标

- 四页导航改用 Rounded `home` / `assignment` / `settings` / `info`，未选中为轮廓、选中为填充，保留文字标签。
- 替换字符式图标、箭头及警告符号；搜索、刷新、备份、写入、复制、删除、文档、目录、下拉与任务状态使用同一套官方 Symbols。
- 工具标题、关于页与危险确认弹窗使用一致的图标风格；错误/警告遵循 MaterialTheme 语义色。
- 前台任务和完成/失败通知不再使用 Android 平台旧图标，改为本地 Symbols 单色矢量。
- 带文字的装饰图标避免重复朗读；没有用小图标替代原有按钮触控区域。浅/深色、动态主题继续使用原主题规则。

### 来源、许可与检查

- 23 个 XML 固定到 Google 官方提交 `737e3324305806514d7909874fa1818ae1808232`，Rounded / weight 400 / grade 0。四页导航各包含 FILL 0/1 两个版本。
- 普通图标 optical size 24，品牌图形 optical size 48；原始路径保留，去除平台 tint，由 Compose 或通知系统负责着色。
- 不引入图标字体、运行时下载、旧版 Material Icons 库或新网络权限。资源随 APK 离线提供。
- 附逐文件来源与 SHA-256 清单，资源内注明修改；关于页可离线查看 Material Symbols 来源及完整 Apache-2.0 许可证。
- 新增离线资源校验并纳入 GitHub 构建；新增 3 项 Android 图标仪器测试（浅色、深色、启动图标/许可），与既有 4 项共同编译。

## 未改变的安全边界

受限真实写入仍要求：已知、可写、未挂载/未映射的普通物理分区，允许名称及类型，等长完整 raw，强制完整备份，明确分区名和风险确认，以及同步/读回校验。动态分区、Virtual A/B、当前活动 A/B 槽、RPMB、userdata、整盘和未知目标不支持。AVB、回滚与设备兼容性未验证。

无自动重试、恢复、回滚、切槽、重启或 AVB 绕过；开始后没有安全取消保证。失败/不确定状态保留写入意图，成功也仅在当前进程内存授权；同次启动的新进程会保守阻止设备操作。不要删数据、卸载或盲目重启来绕过。完整细节见[安全设计](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/SAFETY_DESIGN.md)。

## 验证范围

- 离线脚本校验矢量哈希、资源映射、四组导航状态、启动图标路径与安全区域、许可、旧图标/网络依赖残留。
- 核心 76 项测试会在本次 CI 重新执行；实际测试数量、通过/失败/跳过、Lint 和提交信息由流程从本次报告追加，不复用旧结果。
- Android 主 APK、Lint、测试 APK 均由本次 GitHub 构建检查。**7 项仪器测试仅编译，未在模拟器或真机执行。** 不宣称 UI 或视觉测试已通过。
- 没有新的真机、Root、写入、断电或恢复测试。启动器裁切、主题图标、通知外观、TalkBack 和字体放大仍需设备检查。

## 下载与安装

版本 **0.2.1-raw-preview**，版本码 **4**；最低 API 26，目标 API 35。下载主应用 `YU-Flash-Tool-debug.apk`；`YU-Flash-Tool-androidTest.apk` 仅为测试包。对应源码、测试/Lint 报告、构建身份、许可与 SHA-256 校验表随同一 Release 提供。

这是 Debug 预览，不是生产签名稳定版。临时 runner 的签名可能与旧包不同，不能承诺覆盖安装；不要因签名冲突贸然卸载，尤其有写入意图或不确定状态时。先保留记录、备份及独立救援方式。不要在依赖正常运行的主力设备上将预览当作恢复工具。
