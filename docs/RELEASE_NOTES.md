# 1.0.0

> **本次按用户授权把活动写入改为警告与免责声明确认后的直接 `dd`，移除旧写入检查。** 它能够覆盖真实分区，没有镜像/设备兼容性检查、强制备份或读回验证，可能造成数据丢失、无法启动或变砖。**“正式发行”指版本、稳定签名及发布包装，不是安全验证或机型适配认证。** 本说明是发布输入；构建、签名与上传状态必须由本次实际 CI 证据确认，不表示现已完成。

## 本次变化

### 主页与分区发现

- 主页按钮统一为 **“一键获取分区表”**；运行时实际加载文字为 **“正在读取分区表”**。
- 用户主动点击后申请 Root 并发现分区，不在首次启动时自动申请。表格继续提供搜索、排序、详情与手动读取。
- RPMB 仍在普通内容探测前按别名及真实设备名跳过；不提供 RPMB 读写或密钥功能，也不承诺整盘或所有块设备支持。

### 文件导入不再充当镜像检查

- 从系统文档选择器取得 `content://` URI，将可读取流复制到应用私有普通文件，统计实际字节数。
- 不解析镜像、不计算写入校验哈希，不以格式、类型、空文件、文件与分区相对大小作拒绝条件。
- **sparse、压缩包和未知内容均按原始字节接受，不展开、不解压、不转换。** 接受这些文件不等于支持其刷包语义。提供器读取、URI 授权、私有空间及 I/O 故障仍可导致复制失败。

### 一个危险确认框，随后直接 dd

- 私有复制完成后，一个危险确认框展示目标分区名、设备路径、实际文件字节数、警告与免责声明，明确确认后才提交。
- 删除准确输入目标名、兼容性条件检查和强制备份步骤；直接写入不再使用大小、类型、槽位、AVB、Bootloader、挂载、动态分区、电量、温度或可写性策略。
- 应用内串行执行固定命令，只接受私有源路径和发现目标，保留基本路径约束及 Shell 引用，不提供任意 Shell：

```text
/system/bin/toybox dd if=<引用后的私有文件路径> of=<引用后的已发现 /dev/block 路径> bs=1048576
/system/bin/toybox sync
```

- 两条命令分开调用：只有 `dd` 返回 0 才执行 `sync`。`dd` 非零或异常即终止，无自动重试/回滚；`sync` 错误不能报成功。
- 活动写入不经过旧 `FlashTransaction`、`RootWriter` 或 `VerifiedCopy`，不做旧版固定目标 FD 的备份比对、全量哈希或读回。
- 成功只表示两条命令返回 0，不代表介质内容、可启动性或恢复能力已经验证。源文件字节数不是独立验证出的实际持久写入量。

### 手动备份与任务边界

- 手动“读取”仍使用旧保守 `SafetyPolicy`、目录/空间检查及备份长度、SHA-256、元数据；它是独立操作，可能被拒绝，**不会由直接写入自动触发**。
- 保留当前任务的应用内串行化与重复提交拒绝，但只检测自己的运行任务，不锁定其他进程或其他 Root 工具。
- 旧不确定写入标记不再阻止直接流程。旧 Root 后代 `dd` 可能仍活着，应用空闲或新进程可以操作不证明设备没有其他写入。
- 前台服务、超时、取消、进程结束不能保证后代 `dd` 停止；没有安全取消保证，也没有自动恢复、切槽或重启。

## 重要风险与不支持的保证

1. **任何被接受的文件都可能是错误输入。** sparse/压缩容器会直接覆盖目标；短文件可能保留目标尾部，空文件不构成有效刷写，过长文件可能部分改写后才失败。不会自动填满、清尾、解包或修复。
2. **目标可能仍在使用。** 不做挂载/动态分区/槽位等写入检查，可能损坏正在挂载或映射的存储。另一个进程或工具也不受本应用互斥控制。
3. **失败不表示未写入。** 非零退出、同步失败、超时、取消、掉电或缺少终态日志都可能伴随部分改写或仍在后台写入的 `dd`。
4. **没有兼容性或恢复认证。** 不验证 AVB、回滚索引、Bootloader 状态或机型；Root 不等于 Bootloader 解锁，确认框不证明文件合适。备份的文件哈希也不能证明在线一致性或可恢复。
5. **不要以重试、清数据、卸载或盲目重启代替故障判断。** 先保留日志和已有备份，停止重复操作，由有能力的人员核实进程与设备状态，并独立准备救援方式。

完整边界见[用户指南](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/USER_GUIDE.md)和[安全设计](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/SAFETY_DESIGN.md)。活动源码入口为 [DirectFlash](https://github.com/guo20120523/YU-Flash-Tool/blob/main/core/src/main/kotlin/io/yu/flash/core/DirectFlash.kt) 和 [DirectDdWriter](https://github.com/guo20120523/YU-Flash-Tool/blob/main/app/src/main/java/io/yu/flash/root/DirectDdWriter.kt)。

## 正式发布、稳定签名与安装

- 本次目标版本为 **1.0.0**，版本码 **5**；计划发布公开可下载、稳定签名、`non-debuggable` 的 Release 主 APK，而不是把旧 Debug 包改名。
- 发布配置改为通过受保护的 CI secrets 提供固定 keystore 与签名凭据，不再依赖临时 runner 的 Debug 签名。签名密钥不进入源码或公开附件。配置存在不等于已成功生成/核验产物。
- **稳定发布签名通常与旧 Debug 签名不同，不能覆盖安装旧 Debug 包。** 若安装器提示签名不一致，需要在确认设备操作已结束并保存必要记录、备份后卸载旧包再安装。卸载删除私有记录和暂存，不能保证停止遗留 `dd`，也不能回滚分区内容。
- 后续同应用 ID、兼容版本且使用同一发布密钥的包才能保持正常更新关系；丢失或更换密钥会影响该关系。应核对本次签名证书摘要，不把 APK 哈希混同于证书身份。
- 主应用与名称含 `androidTest` 的测试附件用途不同。源码、许可、测试/Lint 报告、构建身份、APK 摘要和签名核验资料应与同一完整提交对应；以实际发布附件为准。

构建与密钥配置由[构建说明](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/BUILD.md)和[签名说明](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/SIGNING.md)说明；本说明不预先宣称构建、签名核验或公开发布成功。

## 验证范围与剩余待验

- 本轮本地**没有已安装的 SDK/JDK**，未在本地执行新核心测试、Android 编译、Lint 或签名验证。已新增直接路线的内存假写入器/审计测试，不执行 Shell、Android 导入或设备 I/O；执行结果等待本次 CI 报告。
- 历史 **76 项**核心模拟测试验证的是旧受限 raw 策略和 `VerifiedCopy` 等旧代码，不证明新直接路线。即使旧测试继续通过，也不证明它们仍约束活动写入。
- Android UI/图标仪器测试历史上**只编译、未执行**；编译测试 APK 不能写成 UI 测试通过。新危险确认、加载文字、生命周期和运行交互尚需实际执行证据。
- **没有本次真机、Root 写入、断电、启动或恢复测试。** 普通文件模拟、资源检查、Lint、签名验证和正式发布均不提升为硬件安全认证。
- 重点待验包括：原始字节暂存、危险确认与取消、固定路径引用、`dd`/`sync` 失败顺序及无重试、当前任务重复提交、旧标记不拦截、存活后代与外部并发风险、手动读取策略回归和 RPMB 内容探测前排除。

历史证据与未执行项见[测试矩阵](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/TEST_MATRIX.md)和[验证记录](https://github.com/guo20120523/YU-Flash-Tool/blob/main/docs/VERIFICATION.md)。

## 实际 CI 生成证据

本节由**本次运行的真实报告与产物**补充，不复用历史结果或手写推测的通过数。源码说明中的“计划”“待验证”不构成成功证据。

发布前应能从对应运行核对：

- 完整提交、版本/版本码、运行链接及运行状态；失败、跳过或未执行均保留原状态。
- 核心测试 XML 中的实际通过、失败、错误、跳过数量，区分新直接路线与仍保留的旧测试。
- Release Lint、主 APK 和测试 APK 的实际编译状态；单独注明仪器测试是否执行。
- 主 APK 的应用 ID、版本、`debuggable=false`、实际签名验证结果、证书 SHA-256 与产物 SHA-256。
- 与该提交对应的源码和验证附件，以及没有真机写入/启动/恢复验收的限制。

**尚无上述实际证据时，不把本节解读成发布成功报告。**
