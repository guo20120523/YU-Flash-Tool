# 0.2.0-raw-preview · 受限真实 raw 写入

> **这是可实际覆盖分区的实验预览，不是已经真机验收的刷机工具。** 本版从仅备份/导入检查扩展到真实分区覆盖。本地 76 项核心模拟测试已通过；没有进行真实硬件写入或本轮真机测试。本文件是发行说明源文档，GitHub 构建是否成功及其测试/Lint/提交信息，以发布流程在下方动态追加的实际报告为准，不沿用旧版数字。

## 本次主要变化

### 1. 增加真实、单目标的受限写入链路

- 新增 Java `RootWriter`，由已安装 APK 内代码通过 Root `app_process` 启动，不是任意 Shell 或任意写入二进制入口。
- 目标以 `O_RDWR | O_EXCL` 打开，并附加 `O_NOFOLLOW | O_CLOEXEC`；固定同一个设备 FD，贯穿原目标全量哈希、完整写入、`fsync` 和全量 SHA-256 读回，避免在阶段之间重新解析并打开目标路径。
- 核对固定 FD 的块设备类型、设备号、容量与 sysfs 绑定；重新检查真实物理分区、只读/映射/holders/slaves、可读进程挂载命名空间与 swap 状态。必要信息无法确定则拒绝。
- 新增共享核心引擎 `VerifiedCopy`：先验源哈希与原目标全量备份哈希，输出首字节前同步写入阶段，处理合法短读/短写，对零进展、提前 EOF、同步/读回错误或哈希不符直接失败。
- 仅在完整读回且源/目标描述符关闭后，助手发出精确 token/身份/长度/哈希回执。应用核对回执后记录结果，**不把成功描述为可启动**。

### 2. 明确支持范围，不声称 AVB 或机型认证

- 只允许独立、可写、未挂载/未映射、已知类型的物理分区；不支持整盘、RPMB、数据、关键固件、未知目标或任意路径。
- boot 类名称：`boot`、`init_boot`、`vendor_boot`、`recovery`，内容为 BOOT/VENDOR_BOOT；系统文件系统名称：`system`、`vendor`、`product`、`odm`、`system_ext`、`vendor_dlkm`、`odm_dlkm`、`system_dlkm`，内容为 EXT4/F2FS/EROFS。
- 非 A/B 可用无槽位目标；A/B 仅允许明确的非当前槽位，拒绝当前槽、无槽别名和未知槽位。
- 镜像必须为类型一致、整分区等长 raw；不补零、不截断、不清尾，不转换 sparse，不解包压缩或 OTA 包。
- 必须确认 Bootloader 解锁，动态分区与 Virtual A/B 环境整体拒绝。电量至少 50% 且达到用户下限，温度 0–42°C；默认要求充电。
- 移除旧版空设备适配注册表/硬件无条件抛错的永久阻断，改为上述可审计的有限资格。**AVB、回滚索引与设备兼容性仍未验证，不提供兼容设备认证名单。** 允许范围只是限制，不是能正常启动的证明。

### 3. 写前强制备份与明确危险确认

- UI 顺序为：导入并检查 → “检查写入条件” → 完整危险确认。导入自身不触发设备覆盖，仍可“关闭（不写入）”。
- 最终确认列出目标名、槽位、设备路径/设备号、容量、镜像类型/哈希、备份目录与可用空间。必须准确、区分大小写输入分区名，并单独勾选接受 AVB/回滚/设备兼容性未验证风险。
- 强制完整原分区备份、长度/哈希/元数据复核无关闭开关；写前再次检查备份、目标、槽位、构建与环境。
- Root 助手在首字节改写前，要求固定目标 FD 的**整个分区 SHA-256 与原备份一致**。这新增于真实写入路径，不应倒推为旧版独立备份已经有此对照。
- 无自动重试、续写、回滚、重启、切槽、Bootloader 解锁或 AVB 绕过；开始后没有安全取消保证。备份并不赋予应用自动恢复能力。

### 4. Root 锁与进程不确定性处理

- 助手锁与一次性 token 改为设备上 root 所有、精确 `0700` 的 **`/data/yu-flash-tool-writer`**；不是 shell 可写临时目录。
- 校验父目录及锁对象，稳定 `writer.lock` inode 不删除；在排他文件锁下独占创建并同步 `used-<token>`，失败也不重用 token。此锁不约束其他任意 Root 工具。
- 应用在启动助手前以 `AtomicFile` 持久写入意图，同步文件/目录并读回；失败、超时、取消**不清除记录**。
- **成功也保留意图，成功授权仅在当前进程内存中。** 同一次设备启动的新进程不能继承旧成功回执，因此即使先前写入成功，也会保守阻止设备探测、读写、导入与暂存清理。
- 有效旧记录在检测到不同内核 boot ID 后才不再阻挡资格检查；这不是自动恢复，不建议为了互锁而盲目重启。记录损坏需要人工支持，不应删除、清数据或卸载来绕过。
- `MainViewModel` 中 Root 授权/发现/刷新、备份条件、写入条件和清理统一使用共享门闩/互锁检查；操作提交、导入、备份和写入也受约束。日志查看/导出与设置仍允许，设置不能解锁。
- 进程、后台服务或 Root 超时仍可能留下继续运行的助手或部分目标；失败/取消不是“已安全停止”。应保留备份与记录，停止追加设备操作并人工判断。

### 5. RPMB 探测与说明更新

- 按 by-name 名称及解析后的设备名称过滤 RPMB，在 `od` 内容探测前跳过，修正此前普通探测触发 RPMB I/O 错误的源码路径。
- **没有 RPMB 真机回归结果**，也不提供 RPMB 读写、格式化或写密钥功能。
- 首页保持长期通用介绍，不维护逐版本条目或固定测试数字；用户指南、安全设计与文档导航更新真实写入和互锁边界；历史验证证据保留但不提升为当前结果。

## 已知限制与剩余风险

1. **没有新写入链路的硬件写入/故障测试，也没有受支持机型验收清单。** 内核独占打开、Root 管理器、SELinux、`app_process`、挂载命名空间和 sysfs 差异可能导致拒绝，不能移除检查后使用。
2. AVB 签名链、回滚索引、厂商镜像兼容性与设备启动能力未证明。用户接受风险不等于程序验证这些条件；Bootloader 解锁也不意味着任何镜像可启动。
3. 动态分区、Virtual A/B、当前活动 A/B 槽、数据/关键固件/未知目标不支持。较新系统缺失 Virtual A/B 排除信息也拒绝。
4. 字节完全一致与 `fsync` 返回不能保证所有介质/断电语义；应用和 Root 助手无法保证任意时刻安全取消。不会自动撤销已经发生的覆盖。
5. 持久互锁有意保守：新进程在同一次启动内可因旧成功写入而阻止设备操作、导入与清理。不要通过盲目重启、删记录或卸载规避。
6. 备份仅支持明确选择 `/sdcard/download` 或 `/sdcard/Download`；备份和私有暂存都需要空间。空间检查不是预留，镜像/元数据提交不是跨文件原子事务；下载目录可能被其他应用访问或云同步。
7. 本地导入仅接受普通文件。云端流/管道不接受；异常提供器阻塞时不能保证及时取消。成功后不自动清理暂存，备份不会自动删除。
8. 前台服务与唤醒锁不保证存活；本地预算 5 小时。日志可因满盘/损坏而缺失，列表和导出只取最新最多 1000 条事件。
9. 仪器测试 APK 编译不等于执行，旧用户基础/只读反馈不构成当前写入验收。传递依赖完整许可审计与稳定发布签名方案仍需完善。

## 下载与安装（发布后适用）

- 本说明所述版本为 **0.2.0-raw-preview**，版本码 3，最低 API 26、目标 API 35；不是全机型兼容承诺。
- 待 Release 及本次报告生成后，再下载主应用 `YU-Flash-Tool-debug.apk`；`YU-Flash-Tool-androidTest.apk` 是测试包，不是主应用。文件名为拟发布附件约定，不代表现已上传或核验。
- 保留与 APK 同提交的源码、构建身份、报告、许可及校验表；不要将旧预览 APK 当成新功能产物。
- Debug 预览不是生产签名稳定版。临时 runner 的 Debug 签名可能与旧包不同；无法覆盖安装时不要贸然卸载，尤其存在写入意图或不确定状态时，先导出记录并寻求支持。卸载会清除私有记录与暂存，不是安全解锁办法。
- 仅在有授权、受控且准备独立救援方式的测试设备上评估；没有 Root 时仍可查看设置和任务。不要在依赖其正常工作的主力设备上把预览当作恢复工具。
