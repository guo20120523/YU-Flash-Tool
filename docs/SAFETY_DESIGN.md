# 安全设计与未解决边界

[返回首页](<../README.md>) · [用户指南](<USER_GUIDE.md>) · [测试矩阵](<TEST_MATRIX.md>)

## 1. 安全定位

这是**具备实际读取/导入实现、真实写入关闭**的工程，不是已验证刷机工具。安全设计、单元模拟和真实设备验证是三个不同层次，不能相互替代。本文件解释策略及其边界；各版本的实际验证结果与已知问题见对应 [Releases 页面](https://github.com/guo20120523/YU-Flash-Tool/releases)，早期工程证据见[历史验证记录](<VERIFICATION.md>)。

错误目标、镜像或中断可造成数据丢失、无法启动或变砖。在线块级备份不等同于文件系统一致快照；备份文件可读、哈希一致，不等同于具有恢复手段。

## 2. 信任边界与默认拒绝

[核心模型](<../core/src/main/kotlin/io/yu/flash/core/Model.kt>)用 `YES / NO / UNKNOWN` 显式表达未知状态。未知不能等价为否或安全。[安全策略](<../core/src/main/kotlin/io/yu/flash/core/SafetyPolicy.kt>)将读取和写入分离。

### 读取策略

必须有正容量、`/dev/block/` 内的块设备路径和非空身份；拒绝 `Risk.DATA`、挂载状态不是 `NO`、映射状态不是 `NO` 的目标。`userdata`、`metadata`、`cache` 归为 DATA，避免把承载下载目录的数据分区回读到自身。映射/holder 与 `super` 等动态场景不在首版支持范围。

风险分类为 `UNKNOWN` 或 `CRITICAL` 并非单独的备份拒绝条件：若容量、身份、挂载及映射等读取条件全部满足，源码可能允许其进入备份流程。**不要将写入的风险拒绝规则错误宣传成“所有高风险分区都不可读取”。** 这些分区的备份仍可能含敏感数据。

### 写入策略与三重阻断

1. UI 导入结果只显示“不放行刷写”，不提供实际刷写提交入口。
2. 当前操作控制器使用空的 `NoQualifiedDevices`。设备环境也把快照和 AVB 兼容性设为 `UNKNOWN`。
3. [RootDeviceAccess](<../app/src/main/java/io/yu/flash/root/RootDeviceAccess.kt>)的 `write()` 无条件抛出 `SafetyException`，不存在已开放的实际块设备写入命令。

核心策略为未来已审核适配准备：工具就绪、BOOT_CHAIN 目标、BOOT/VENDOR_BOOT 类型一致、A/B 已知、确认解锁、快照安全和 AVB 兼容、最低电量至少 50%、温度 0–42°C、按设置要求充电、注册表精确匹配构建指纹/分区/设备号/镜像哈希并检查回滚保护。配置默认限制非当前槽位；首版要求镜像与分区完整等长，不补零、不截断、不清尾。**这些检查不是已实现设备适配的证明。**

没有专家绕过、批量刷写、任意 Shell、自动重试、自动重启、自动续写、自动回滚或 AVB 覆盖/关闭校验路径。温度与电量阈值是应用策略而非通用硬件安全保证。

## 3. Root 与目标身份

[Root 执行器](<../app/src/main/java/io/yu/flash/root/RootShell.kt>)仅供包内受控模板使用，通过字符白名单限制路径和名称；UI 不接受 Shell 字符串。用户主动申请后验证 uid 0。工具自检会写应用私有普通临时文件，**不是零文件写入**，但不以块设备为输出。

[分区发现](<../app/src/main/java/io/yu/flash/root/PartitionRepository.kt>)读取限定 by-name 目录，解析符号链接，检查实际块设备、sysfs 设备号与扇区容量、`/proc/1/mountinfo`、dm/holders 和内容头；按设备号合并展示别名。稳定目标比较包括名称、所选别名、规范设备路径、设备号、容量、槽位和类型，别名展示列表不作为稳定身份。

检查不是原子锁：发现、再次检查与打开设备之间仍存在竞态；挂载命名空间、sysfs 图和 Root 实现也未完成设备级验证。未来真实写入需要绑定已打开目标文件描述符的身份校验及设备级 AVB/快照证据，不能简单把抛错替换成 `dd`。

## 4. 实际备份协议

[备份实现](<../app/src/main/java/io/yu/flash/root/RootDeviceAccess.kt>)执行：

1. 读取策略检查与目标刷新；比对稳定身份。
2. 重新验证用户明确选择的下载目录和空间，保留至少 64 MiB 余量。
3. 在设备目录下以时间戳和 UUID 创建任务叶目录；叶目录使用不带 `-p` 的 `mkdir`，碰撞时失败，不复用旧任务。
4. 校验别名解析与块设备类型，`dd` 读取到 `.partial` 普通文件，随后 `sync`、校验实际长度及 SHA-256。
5. 再次检查目标身份，再哈希持久化文件。
6. 写入含身份、长度、哈希及警告的元数据，最后提交镜像和元数据；调用方再做长度、哈希及元数据状态、字节数及哈希字段检查。

### 不应夸大的保证

- SHA-256 检查的是备份文件，未构成独立原设备再次逐字节一致性证明。
- 元数据是提交标记，不是数字签名；当前 `verifyBackup()` 解析配套元数据的 `state=VERIFIED`、`bytes`、`sha256`，但不校验全部身份字段，也不是抗篡改签名。
- 镜像与元数据的两次重命名不是跨文件原子事务。提交失败时尝试将镜像改回 `.partial`，但该恢复为最佳努力；掉电、Root 失效或存储错误可留下不完整/不一致状态。
- 空间检查不是容量预留；其他进程仍可能耗尽空间。共用目录上的外部并发和干预未经验证。
- 不覆盖意图通过唯一目录和存在性检查实现，不能宣传为对恶意 Root 对手或任意文件系统故障的绝对保证。

## 5. 导入、格式与哈希

[导入器](<../app/src/main/java/io/yu/flash/storage/ImageImporter.kt>)仅接受 `content://`，不以提供器展示名拼接路径、不信任声明长度。导入目录使用 UUID，按实际读取字节数限制为目标容量内，每块写入前检查 64 MiB 余量，完成后同步并检查长度。通过 `fstat` 拒绝非普通文件，不支持云端流、管道或流设备。原文档不改写，私有副本由用户手动清理。

[镜像检查器](<../core/src/main/kotlin/io/yu/flash/core/ImageInspector.kt>)以内容签名识别 BOOT、VENDOR_BOOT、AVB、EXT4、F2FS、EROFS 等，拒绝 sparse、压缩格式和未知签名；boot 类检查头版本、页大小和载荷长度等基础结构。它不是完整格式认证、签名验证、AVB 校验或硬件匹配器。将文件重命名为分区名不改变内容或兼容性。

取消通过协程检查、`CancellationSignal` 和关闭描述符尽力处理。**文档提供器在 `openFileDescriptor()` 阻塞时可能忽略取消，不能承诺及时结束。** 普通文件资格检查发生在打开返回后，无法先验消除这一风险。

## 6. 核心写入事务：设计而非硬件交付

[FlashTransaction](<../core/src/main/kotlin/io/yu/flash/core/FlashTransaction.kt>)当前可在假设备/普通文件上模拟以下次序：

```text
IMAGE_CHECK → TARGET_CHECK → CONFIRMED → BACKUP → BACKUP_VERIFY
→ NORMALIZE → RECHECK → WRITING → SYNCING → READBACK → SUCCESS
```

要求显式确认和准确输入目标名；重新检查导入文件；备份并验证；只重命名私有副本且拒绝重名；写前再次验证备份、身份、槽位、构建及策略；同步后对所声明范围做哈希读回。异常记录 `FAILED`，取消记录 `INTERRUPTED`，不会自动重复写入。`SUCCESS` 仅表达被校验字节相符，不保证可启动。

当前真实环境会在前置检查或硬件适配器处拒绝，不应把该流程图当作已经可以完成刷写的用户操作指南。

## 7. 并发、日志和生命周期

[操作控制器](<../app/src/main/java/io/yu/flash/OperationController.kt>)拒绝重复提交；共享 `TransactionGate` 用 `tryLock` 实现进程内互斥，不排队重复点击。它不是跨进程/全系统锁，无法约束其他 Root 工具。

[任务日志](<../app/src/main/java/io/yu/flash/storage/TaskJournal.kt>)使用 SQLite 并设置 `synchronous=FULL`；启动时将未结束任务标为中断，不重新执行操作。日志满盘或损坏也可能让终态记录失败，因此没有记录不能证明从未开始。列表/导出只读取最新最多 1000 条事件，并非无限完整审计档案。

[前台服务](<../app/src/main/java/io/yu/flash/TaskService.kt>)使用 `START_NOT_STICKY`，前台 dataSync 通知、5 小时唤醒锁/本地预算，以及系统超时回调。系统杀进程、设备关机和提供器不配合仍可能打断/拖延；这些生命周期行为未完成仪器或真机验证。

Root 输出重定向到临时普通文件而非管道，并检查输出大小及超时。清理时强制结束**直接进程**；**不能保证 `su` 的所有后代进程被终止**。取消后的外部命令状态须重新确认，不能把异常当成安全停止或允许立即重试的依据。

## 8. 隐私与发布门槛

[应用清单](<../app/src/main/AndroidManifest.xml>)不声明网络权限，关闭系统应用数据备份；这不约束外部文档提供器或下载目录同步服务。私有日志摘要可能含路径或错误信息；用户导出采用字段白名单，排除路径、指纹、内容及错误原文，但仍保留分区名、时间和任务 ID。

真实写入开放前至少需要：设备适配审核、已打开目标身份绑定、明确快照/AVB/回滚证据、断电和进程故障方案、离线恢复路径、[测试矩阵](<TEST_MATRIX.md>)中设备项证据及第三方许可材料。任何单元测试成功都不能替代这些门槛。
