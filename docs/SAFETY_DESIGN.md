# 安全设计与未解决边界

[返回首页](<../README.md>) · [用户指南](<USER_GUIDE.md>) · [测试矩阵](<TEST_MATRIX.md>)

## 1. 定位：强制备份与读回，不是兼容性或安全认证

活动写入保留固定 Toybox `dd`，在明确确认后**自动备份完整目标分区并强制复核，写前测量源文件实际长度/SHA-256，写入与同步后读回精确字节范围，再复核源文件，全部满足才成功**。备份和读回不可跳过，也不由可关闭开关控制。

这不是恢复旧受限 raw 写入事务。没有恢复镜像格式、AVB、回滚索引、槽位、Bootloader、电量/温度等兼容性准入；没有固定同一目标 FD 的备份/写入/读回链路。错误目标、错误文件、并发访问、中断或供电故障仍可造成部分改写、数据丢失、无法启动或变砖。正式发行和摘要相符均不是设备认证。

强制备份复用现有 `SafetyPolicy.backup` 与备份实现，故**备份拒绝即不能进入写入**。DATA、挂载/映射或其状态未知、容量/身份未知及目录/空间问题等均可能阻断；不能声称所有发现目标无条件可写。

## 2. 活动路线与成功条件

[DirectFlash](<../core/src/main/kotlin/io/yu/flash/core/DirectFlash.kt>)协调确认、应用内任务门闩、备份/复核、源摘要、写入/读回及日志；[DirectDdWriter](<../app/src/main/java/io/yu/flash/root/DirectDdWriter.kt>)将固定命令交给 [RootShell](<../app/src/main/java/io/yu/flash/root/RootShell.kt>)。

```text
content URI → 私有普通文件副本 + 实际字节数
→ 单个危险确认（目标名、路径、字节数、警告与免责声明）
→ 明确确认 → 现有策略准入 / 自动完整备份
→ verifyBackup（备份长度、SHA-256、提交元数据）
→ 写前源文件实际长度 + SHA-256
→ dd → 仅返回 0 后独立 sync
→ 只读助手流式读回目标 [0, 写前源长度)
→ 读回实际长度和 SHA-256 必须等于写前源
→ 再测源长度/SHA-256，检测期间修改
→ 全部通过才 SUCCESS
```

| 项目 | 当前边界 |
| --- | --- |
| 自动完整备份 | 强制，沿用保守读取策略；任何拒绝或失败不得继续 dd |
| 备份复核 | `verifyBackup` 强制核对文件长度、摘要及提交元数据；不能仅凭备份返回值或镜像存在放行 |
| 输入实际长度、SHA-256 | 写前测量，供读回比较；写后再次测量源以检测修改，不是格式或兼容性认证 |
| 输入格式与等长策略 | 不解析/转换，不要求与分区等长；短输入只验证前缀，超长可能部分写入后失败 |
| 目标使用状态 | 继承备份的 DATA、挂载/映射/未知状态、身份和容量限制；不是贯穿写入时刻的全套安全检查 |
| 槽位、AVB、回滚、Bootloader | 未恢复兼容性准入，不提供绕过能力 |
| 电量、充电、温度 | 未恢复旧准入；用户需独立判断电源风险 |
| 写后读回 | 精确源长度范围的实际长度/SHA-256 与写前源比较；不验证短镜像尾部 |
| 旧写入助手与固定 FD | 不调用旧 RootWriter/VerifiedCopy 事务；读回助手只读，不固定贯穿备份/写入/读回的目标 FD |
| 失败 | 不重试、不回滚、不自动重启；写后失败或中断可能已经损坏目标 |

## 3. 强制完整备份的准入与提交

[SafetyPolicy](<../core/src/main/kotlin/io/yu/flash/core/SafetyPolicy.kt>)的 `backup(target: Partition)` 要求正容量、有效 `/dev/block/` 路径与 `major:minor` 身份；拒绝 `Risk.DATA`、`mounted != Truth.NO`、`mapped != Truth.NO`。**`Risk.UNKNOWN` 或 `Risk.CRITICAL` 分类本身不一定拒绝读取**，不能把“未知挂载/映射/身份拒绝”改写成“所有 UNKNOWN 风险都禁止”。

[RootDeviceAccess](<../app/src/main/java/io/yu/flash/root/RootDeviceAccess.kt>)复核目标身份、备份策略、明确选择的目录与空间：

- 只接受 `/sdcard/download` 或 `/sdcard/Download`，一处不存在/不可写时不静默回退另一处。
- 至少需要**完整目标分区容量加 64 MiB**余量，短镜像不会缩小备份；空间检查不是预留。
- 在唯一任务叶目录创建 `.img.partial`，不复用已有任务目录，读取整个分区，执行同步并检查长度和 SHA-256。
- 复核读取后的目标身份与备份文件摘要，再提交最终镜像和元数据。元数据记载长度、摘要及 `VERIFIED` 状态等；镜像/元数据不是跨文件原子提交。
- 自动写入必须再调用 `verifyBackup` 核对备份文件长度/摘要及提交元数据；调用异常、缺失或不符都不得进入 `dd`。
- 读取路径已有的身份复核、互锁、目录或空间拒绝也随复用生效。不能通过删标记或绕过备份来“恢复”写入资格。

备份边界：文件摘要不是独立原设备再次全量一致性证明，不是签名，也不能抵御有能力的 Root 并发篡改；在线块读取不是一致性快照。共享下载目录可被其他进程修改或耗尽空间，孤立镜像或 `.partial` 不是完整成功。备份存在不代表设备具备外部恢复途径。

## 4. 固定 dd、路径约束与原始字节

`DirectDdCommand.copy(source: String, target: String): String` 生成固定命令：

```text
/system/bin/toybox dd if=<引用后的私有文件路径> of=<引用后的已发现 /dev/block 路径> bs=1048576
```

仅成功返回后使用另一条独立命令：

```text
/system/bin/toybox sync
```

源路径为绝对路径，拒绝 NUL/换行并正确引用单引号；目标位于 `/dev/block/`，使用受控字符并禁止 `.` / `..` 路径段等非法路径。UI 不接受任意 Shell 或任意目标路径。这些约束限定参数，不是镜像兼容性或目标身份持续绑定。

`dd` 按输入 EOF 写入，不补零、清尾、按分区容量截断、不展开 sparse 或解压 archive。源比目标短时只改写前缀；过长时可能部分改写后才遇到容量/I/O 错误；空输入也不构成有效刷写。没有按格式或等长判断兼容性的旧准入。

## 5. 源摘要、只读读回与检测范围

[导入器](<../app/src/main/java/io/yu/flash/storage/ImageImporter.kt>)从 `content://` 提供器复制到私有普通文件并统计实际字节数；原始文档不改写，提供器展示名不作为路径。不调用旧 [ImageInspector](<../core/src/main/kotlin/io/yu/flash/core/ImageInspector.kt>)提供格式放行，不展开或转换内容。复制失败、URI 撤权、空间不足和不响应取消仍是可能的 I/O 问题。

自动备份及 `verifyBackup` 完成后，写入流程重新读取私有源文件，计算**实际长度和 SHA-256**，作为写前基准，不只相信提供器长度或导入时统计；实际长度与已确认的导入字节数不符，或摘要无效时不得调用 `dd`。这不是要求源与分区等长，也不是镜像解析。

写入和 `sync` 成功后，Root 只读助手通过已安装 APK 的 `CLASSPATH` 与 `app_process` 启动：

- 只读打开目标，流式计算范围 `[0, 写前源长度)` 的摘要并报告实际长度；不执行写入或回滚。
- 范围不足、异常或助手失败不能当作读回成功，不能只看是否产生一个摘要字符串。
- 不生成另一份与镜像一样大的临时读回文件；使用有界缓冲，不以 `dd | sha256sum` 等可能掩盖上游读取失败的 Shell 管道判定成功。
- 实际读回长度/SHA-256 必须等于**写前源**。再次测量源长度/SHA-256，若修改或测量失败也不得成功；不能只拿读回与已改变的源比较。

**短镜像仅校验前缀，未触及尾部不验证。** 完整备份覆盖全分区与写后验证整个分区是不同概念；不得宣传“完整分区写后验证”或“尾部保持不变已证实”。摘要相符也不证明格式、AVB、回滚、启动、恢复或掉电后的持久性。

此链路不把源和目标固定在一组贯穿任务的独占 FD 中，不排除外部进程在检查间修改、替换再恢复内容的竞态。尤其 `dd` 读取到 EOF：若源在写入期间被追加、随后恢复，额外内容可能写到检测前缀以外而不被前后源摘要发现。读回相符依赖暂存源在期间稳定，不能证明实际写入范围没有越过检测前缀。备份、dd 和读回分别打开路径；读回设备号正确也不能证明 dd 当时打开的是同一个对象。源复核是修改检测，不是任意 Root 对手下的不可变性或同 FD 身份证明。

## 6. 失败与成功语义

1. 未明确确认，不提交写入任务。
2. 备份准入、目录/空间、完整备份、`verifyBackup` 或写前源测量失败，不启动本次 `dd`。
3. `dd` 非零或异常即失败/中断，不调用后续成功流程，不自动重试/回滚。
4. 只有 `dd` 返回 0 才执行独立 `sync`；同步失败不能成功。
5. 读回错误、范围总长度不足/提前 EOF、长度/摘要不符、源修改或源复核失败都不能成功。此时目标可能已经改写。
6. 全部必要步骤完成才记录 `SUCCESS`；日志中的字节数和摘要不是可启动性、可恢复性或掉电持久性证明。

`sync` 加读回不是固定目标 FD 的持久事务；缓存、内核、驱动和存储硬件的掉电语义不由这些检查认证。失败可能在首字节之前或部分写入之后，退出码不能还原整个设备状态。不要将 FAILED/INTERRUPTED 解释为“没有写入”。

## 7. 当前任务、生命周期与旧互锁

危险框展示目标名、路径、字节数及免责声明，确认后才提交。`TransactionGate` 和应用内状态串行化当前任务，重复提交拒绝而不是排队。**不锁其他进程或 Root 工具，也不能可靠识别旧应用进程遗留的 `dd`。**

[操作控制器](<../app/src/main/java/io/yu/flash/OperationController.kt>)与[前台服务](<../app/src/main/java/io/yu/flash/TaskService.kt>)管理通知、唤醒锁、当前任务和超时；前台运行不是不被杀进程的保证。Root 执行器只能尽力结束直接 `su`，**不能保证后代 `dd` 已退出**。取消、超时、服务停止、页面空闲和失败日志都不是安全停止回执。

旧 [WriteInterlock](<../app/src/main/java/io/yu/flash/root/WriteInterlock.kt>)仍在读取/备份路径中；复用备份意味着其拒绝可能阻止自动备份和后续写入。**这不等于恢复旧 RootWriter 的一次性 token、root 独占锁、固定 FD 或为当前 dd 建立持久意图/后代生命周期保证。** 不应通过删标记、重开应用或盲目重启推断设备已安全。

[任务日志](<../app/src/main/java/io/yu/flash/storage/TaskJournal.kt>)把已准入的短 SQLite 提交与列表刷新分开：提交失败仍抛错；提交成功后的列表刷新失败显示独立警告，不因此追加与已持久化 SUCCESS 矛盾的 FAILED。此短提交不可取消区不覆盖设备 I/O，也不是断电保证。重开后将未结束任务标为中断，不重跑；日志缺失、满盘或终态写入失败也不证明未改写。保留记录和备份，停止重复操作，由有能力的人员核实进程与设备状态。无自动恢复、回滚、重试、切槽或重启。

## 8. 分区发现与 RPMB

[分区发现](<../app/src/main/java/io/yu/flash/root/PartitionRepository.kt>)从限定 by-name 路径解析设备号、容量和别名，采集内容头及挂载/映射信息。不是扫描所有设备；发现不等于写入瞬间复核，更不承诺整盘支持。

用户通过“一键获取分区表”发起 Root 授权，运行时显示“正在读取分区表”。工具自检使用普通临时文件，不以块设备为输出。RPMB 按别名与真实设备名在 `od` 等内容探测前排除，不提供 RPMB 功能，不应以普通读取或写密钥试探。

## 10. 隐私与待验证事项

[应用清单](<../app/src/main/AndroidManifest.xml>)不声明 INTERNET 权限；外部提供器、共享目录同步及其他 Root 进程不受此限制。完整备份可能包含密钥或个人数据，脱敏导出仍含时间、任务 ID 和分区名，分享前应审查。

本次核心测试、Android 构建/Lint、签名证书比对及发布均等待实际 CI/产物证据；文档编辑未执行这些操作。没有本次真实硬件写入、断电、启动或恢复验收。发布使用原证书、不更换密钥是发布要求，不是签名已核验的结论。详见[测试矩阵](<TEST_MATRIX.md>)与[验证记录](<VERIFICATION.md>)。
