# 用户指南

[返回首页](<../README.md>) · [构建说明](<BUILD.md>) · [安全设计](<SAFETY_DESIGN.md>)

> 本指南介绍通用流程；下载、版本变化、验证结果及已知问题请查看所选版本的 [Releases 页面](https://github.com/guo20120523/YU-Flash-Tool/releases)。**受限 raw 写入会真实覆盖设备分区，尚无真机写入验收。** AVB、回滚索引、设备兼容性未被证明；备份与读回一致不保证能启动或恢复。本应用没有自动恢复入口。

## 1. 启动与 Root

应用有“主页、任务、设置、关于”四个页面。首次打开不会自动申请 Root；阅读用途后，在主页点击“了解用途并申请 Root”。Root 管理器的授权提示由设备自身环境决定。未授权时仍可查看设置和历史任务。

检测检查 `su` 是否取得 uid 0，并用应用自有普通临时文件验证 Toybox 和 Root 写入组件的行为。自检会执行普通文件写入、同步和读回，**不写块设备，也不是完全无文件写入**。缺少 `su`、拒绝授权、超时、工具不可用或无法读取必要设备信息会阻止继续。Root 已取得不代表 Bootloader 已解锁。

如出现超时，不要连续点击重试。直接 `su` 进程终止不证明其后代助手已停止，须保留任务记录并核实状态。应用不提供任意 Shell 命令入口。

## 2. 浏览分区

主页提供名称搜索、按名称/大小/类型排序、槽位与风险筛选以及“仅可读取”筛选。可上下滚动主页、左右滚动五列表格；点击分区名称或大小查看真实块路径、设备号、原始字节数、槽位、风险、挂载/映射状态和重复别名。

- 只从限定的常见 by-name 路径发现目标，不承诺列出全设备所有分区。
- RPMB 是特殊协议设备：按别名和真实设备名过滤，在 `od` 内容读取之前跳过；不应对其做普通读写、格式化或密钥试验。
- 类型来自内容签名，不凭扩展名判定；名称、容量相同也不证明兼容。
- “仅可读取”是当前本地策略筛选，不代表执行时 Root、空间及身份检查必然通过。
- `userdata`、`metadata`、`cache` 等 DATA、挂载中/挂载未知及映射目标被读取策略拒绝。写入限制更严格，见第 4 节。列表显示或导入成功不构成写入许可。

## 3. 读取并备份

1. 在“设置”中明确选择备份父目录 `/sdcard/download` 或 `/sdcard/Download`。默认前者，不存在或不可写时不会静默换成后者，也不支持任意目录。
2. 点击目标的“读取”，核对目标、容量、保存目录及可用空间。
3. 理解在线读取和隐私风险后点击“理解风险并备份”。Android 13+ 可能请求通知权限；运行期间使用前台服务，系统仍可能终止进程。
4. 等待任务结论。备份读取阶段没有可靠百分比，不定进度条不是精确完成比例。

设备端输出示意（不是仓库文件）：

```text
<明确选择的下载目录>/YU-Flash-Tool/<设备标识>/<时间戳>-<任务ID>/
    <分区名>.img
    metadata.json
```

备份需要整分区大小加至少 **64 MiB** 余量。实际读取先写 `.img.partial`，完成长度、目标身份及文件 SHA-256 复核后提交镜像和元数据；元数据含分区、设备号、构建指纹、字节数和哈希等。独立任务目录用于避免覆盖已有备份。

**完成条件不是“出现 .img 文件”。** 必须检查任务验证结果并保留配套元数据。失败、掉电、进程退出或提交失败可留下不完整文件；改回 `.partial` 仅为最佳努力，不能自行改后缀冒充完成。单独读取备份未做独立原设备全量哈希对照，不保证在线文件系统一致性或可恢复性。写入事务还会在首字节改写前增加原目标全量哈希对照。

下载目录不是应用私有空间，备份可能含密钥、身份信息或个人数据。避免共享、云同步与无关应用访问。不要把备份当作本应用能够自动恢复的承诺。

## 4. 导入 → 条件检查 → 真实写入确认

### 4.1 导入本地镜像（此步不写设备）

1. 点击目标行的“写入检查”，通过系统文档选择器选择本地镜像。
2. 仅接受 `content://` URI 且文件描述符为普通文件；云端流、管道、流设备不接受。先把云端文件保存到本地再选择。
3. 应用复制到私有暂存，按实际读取字节数检查目标容量上限和可用空间，并计算 SHA-256。原始文档不改写。
4. 空文件、未知内容、截断 boot 镜像、Android sparse、压缩包/压缩镜像/OTA 包被拒绝；改成 `.img` 后缀不能改变内容。
5. 查看“镜像检查 · 尚未写入”中的目标、槽位、容量、类型、哈希和强制备份目录。只想检查时选择“关闭（不写入）”。

EXT4/F2FS/EROFS/AVB 等签名被识别，不等于文件系统、签名、AVB 或兼容性已完整验证；能检查的类型也不一定能写入，例如 `vbmeta` 不在写入范围。异常文档提供器可能在打开时忽略取消，不能保证及时退出。

### 4.2 检查写入条件

继续“检查写入条件”会刷新目标与环境并检查备份空间，必须同时满足：

| 条件 | 允许范围与拒绝边界 |
| --- | --- |
| 物理身份 | 已确认可写的独立物理分区；拒绝整盘、RPMB、只读、映射/被持有或拓扑未知对象 |
| 使用状态 | 明确未挂载；Root 助手在写前进一步检查进程挂载命名空间与 swap 使用状态 |
| boot 类 | `boot`、`init_boot`、`vendor_boot`、`recovery`，且当前内容为 BOOT/VENDOR_BOOT |
| 系统文件系统 | `system`、`vendor`、`product`、`odm`、`system_ext`、`vendor_dlkm`、`odm_dlkm`、`system_dlkm`，且当前内容为 EXT4/F2FS/EROFS |
| 镜像 | 内容类型与目标一致，完整 raw，实际长度严格等于分区；不补零、截断、清尾或转换 sparse |
| 槽位 | 非 A/B 允许无槽位目标；A/B 仅明确非当前槽位，拒绝当前槽、无槽别名或未知槽位 |
| 系统环境 | 确认 Bootloader 解锁；动态分区与 Virtual A/B 环境整体拒绝，不将“当前未合并快照”当作支持 |
| 电源与温度 | 电量至少 50% 且达到用户设置下限，温度 0–42°C；默认要求充电，未知必要读数拒绝 |
| 存储 | 私有镜像暂存和完整备份均需空间，备份检查保留至少 64 MiB 余量；空间检查不是预留 |

这些名称允许 `_a` / `_b` 后缀，但必须符合槽位规则。数据、关键启动固件、`vbmeta`、动态及未知目标不允许写入。属性探测不能证明设备适配：源码要求排除 Virtual A/B，较新系统上相关属性缺失也会拒绝；不能自行修改属性绕过。

### 4.3 最终危险确认

条件满足后显示“最终确认 · 真实覆盖分区”，列出完整目标名、槽位、设备路径、设备号、容量、镜像类型与 SHA-256、强制备份目录和可用空间。

提交前必须：

- 阅读失败可能造成部分改写、数据丢失、无法启动或变砖的警告；具备独立于应用的外部救援手段。
- **显式勾选接受 AVB、回滚索引与设备兼容性未验证的风险。** 这只是风险接受，不是通过了兼容性验证，也不是关闭 AVB。
- **完整、区分大小写输入目标分区名。** 不能使用相似名称，也不能带额外空格。
- 最后点击“备份并真实写入”；取消此确认不会提交写入。条件还会在事务内重新检查。

### 4.4 提交后的实际顺序

```text
重新检查镜像与目标 → 强制完整备份 → 复核长度 / SHA-256 / 元数据
  → 仅规范命名私有副本 → 再复核备份、身份、槽位、构建与环境
  → 持久保存写入意图 → 启动 RootWriter
  → 固定独占设备 FD → 校验镜像全量哈希 + 原目标全量哈希等于备份
  → 记录写入阶段 → 写入完整镜像 → 同 FD fsync → 同 FD 全量哈希读回
```

实际设备写入由 Java `RootWriter` 经 `app_process` 执行，不是将块设备路径交给一个可随意重开的 `dd` 写命令。强制备份与完整哈希比对没有关闭开关。只有助手返回精确匹配的身份、长度、哈希回执后，应用才接受验证结束。

**开始写入后没有安全取消保证。** 不自动重试、续写、回滚、重启或切槽；不提供 AVB 关闭、Bootloader 解锁或批量刷写。即使显示读回一致，仍可能不兼容或无法启动。

## 5. 任务、后台、中断与互锁

“任务”页列出阶段、时间、任务 ID、槽位、字节数及可用退出码：导入 `SUCCESS` 只表示导入检查完成，备份 `SUCCESS` 只表示文件复核完成，写入 `SUCCESS` 只表示全分区字节与输入相符。不要统称为“设备已可启动”。

任务使用前台服务、共享进程内互斥和唤醒锁，源码设定 5 小时预算。这不是持续运行保证，也不是硬件验收；切换页面不发起新任务，重复提交拒绝而非排队。系统超时、杀进程、掉电或后台失败都可能中断应用，而 Root 后代助手状态仍不确定；界面不忙或显示失败不等于安全停止。

### 持久写入意图如何影响后续操作

- 启动 Root 助手前，应用使用 `AtomicFile` 持久保存含本次内核启动 ID、任务 token 与目标名的意图记录；失败、超时、取消不会删除它。
- 成功时也保留记录，仅在**当前进程内**记住已验证 token。原进程可在其他条件满足时继续；**同一次设备启动内，新应用进程即使面对先前成功的写入，也会保守阻止设备操作、导入和暂存清理**。
- 设备探测/刷新、备份条件、写入条件、实际读写、导入和清理均受到共享门闩/互锁检查。查看记录、导出脱敏日志与修改设置仍允许，修改设置不能解锁。
- 只有可读取且有效的旧记录对应**不同内核启动 ID**时，旧记录才不再阻挡资格检查；记录不是自动恢复命令，也不因此删除。**不要为解锁而盲目重启设备。** 应先保留备份和日志，由人工判断设备状态与救援方案。
- 损坏记录不会仅靠换一次启动自动变得可信，需要人工支持处理。不要清数据、卸载、删除锁/token/意图记录或绕过检查来重试。

新进程会把未结束任务记为 `INTERRUPTED`，不会恢复执行。持久意图比任务日志更保守：日志可能写入失败，缺少终态不证明未写过。遇到失败应保留备份、暂存与记录，停止追加设备操作并寻求支持。

## 6. 设置与清理

- 外观：跟随系统/浅色/深色、Android 12+ 动态取色、紧凑列表、二进制容量单位。
- 备份：仅支持两种明确大小写的下载目录，不静默回退。
- 写入：最低电量可选 50%–100%，温度范围固定 0–42°C，默认要求连接电源。这是应用策略，不是 Android 官方统一安全标准。
- 强制备份与 SHA-256 不可关闭；显示高风险目标或更多诊断不会绕过策略。
- “任务完成通知”不关闭运行中的前台服务通知；可见性还受系统权限影响。
- “清理所有私有暂存镜像（保留备份）”只在无运行任务、取得共享门闩且互锁允许时执行；不会删除下载目录备份，也不是互锁重置入口。成功后不自动清理暂存。

## 7. 导出与隐私

在“任务”页选择“导出脱敏记录”，阅读说明后选择保存位置。导出仅含时间、任务 ID、分区名、槽位、阶段、字节数和退出码，不含指纹、路径、镜像内容或错误原文；仍非完全匿名。即使写入互锁阻止设备访问，日志导出仍可用。

应用清单不声明网络权限，所读源码无广告/分析 SDK 配置；外部文档提供器和同步软件不受此保证约束。卸载会删除私有记录、写入意图及暂存，下载目录备份通常仍在；不可用卸载来绕过不确定状态。

遇到设备 I/O 错误、互锁或不确定后台状态，停止重复操作并保留证据；不要做格式化、写密钥、盲目重启或写入试验。第三方许可情况以[声明及待办](<../THIRD_PARTY_NOTICES.md>)为准，不代表全部材料已附齐。
